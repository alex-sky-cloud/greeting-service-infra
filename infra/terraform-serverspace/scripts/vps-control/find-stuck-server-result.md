# Разбор вывода `find-stuck-server.sh`

Пример:

```bash

./scripts/find-stuck-server.sh lt6334455
```

## Что делает скрипт

| Шаг | Действие |
|-----|----------|
| 1 | Запрашивает задачу `lt...` из лога Terraform |
| 2 | Показывает **все** isolated-сети проекта (id сети вторым аргументом не нужен) |
| 3 | Перебирает id серверов в диапазоне `l44s1304950`–`l44s1304959` |
| 4 | Выводит полный список VM проекта |

Скрипт **только диагностирует**. Удаление — с флагом `--delete` и только при `Failed` (см. `find-stuck-server.md`).

## Блок `=== task lt6334455 ===`

```json
"is_completed": "Completed"
"server_id": "l44s1304847"
```

| Поле | Значение | Смысл |
|------|----------|--------|
| `is_completed` | **Completed** | Задача завершилась **успешно** (не зависание) |
| `server_id` | l44s1304847 | VM, которую создавала **эта** задача |
| `location_id` | ds1 | Москва (DataSpace) |

Это **старая** задача от первого `apply` (01.07). Сервер `l44s1304847` в текущем списке VM **нет** — уже удалён или заменён новым apply.

Если бы было `Failed` — искали бы «призрака» по `server_id` и смотрели `delete-stuck-server.md`.

---

## Блок `=== network l44n752 ===`

| Поле | Значение | Смысл |
|------|----------|--------|
| `server_ids` | `[]` | К сети **не привязана** ни одна VM |
| `state` | Active | Сеть жива в проекте |
| `tags` | terraform | Создана Terraform |

**«Хвост»** от неудачного apply: в `terraform.tfstate` может быть `l44n752`, а рабочие VM сидят в **l44n753**.

Сеть можно удалить:

```bash

./scripts/delete-network.sh l44n752
```

Если ошибка `Servers are connected` при пустом `server_ids` — баг провайдера, см. `delete-stuck-server.md`.

## Блок `=== probe server ids ===`

Перебор id вокруг текущих серверов. Ожидаемые строки:

```
FOUND l44s1304954 postgres-1 Active HTTP:200
```

| id | Имя | Статус |
|----|-----|--------|
| l44s1304954 | postgres-1 | Active |
| l44s1304955 | gitlab-1 | Active |
| l44s1304956 | k8s-control-plane-1 | Active |
| l44s1304957 | k8s-apps-1 | Active |

Это **актуальная** инфраструктура (второй успешный apply).  
`l44s1304847` из задачи в probe **не попал** — его уже нет.

> Если строки probe выглядят как ` HTTP:200s1304954` — артефакт CRLF в Git Bash; в скрипте исправлено.

```
count: 4
```

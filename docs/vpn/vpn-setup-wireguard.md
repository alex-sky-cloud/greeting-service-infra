# Личный VPN на VPS: WireGuard от настройки до ежедневного использования

> Инструкция рассчитана на один VPS с Ubuntu 22.04/24.04 или Debian 12+ и один или несколько личных устройств. WireGuard создаёт зашифрованный туннель между устройством и VPS; при полной маршрутизации внешний IP для сайтов будет IP-адресом VPS. Несколько VPS в разных странах и переключение между ними — в разделе [Несколько VPS в разных локациях](#несколько-vps-в-разных-локациях).

## Что понадобится

- VPS с публичным IPv4-адресом, Ubuntu 22.04/24.04 или Debian 12+, минимум 1 vCPU, 512 МБ RAM и доступом `root` по SSH.
- Разрешённый входящий UDP-порт `51820` в панели провайдера и на сервере.
- Публичный IP-адрес VPS либо доменное имя, указывающее на него.
- Устройство-клиент: Windows, macOS, Linux, Android или iPhone/iPad.
- Официальное приложение WireGuard для этого устройства.

Не используйте VPS для действий, нарушающих закон, условия провайдера или правила используемых сервисов.

## Схема работы

```text

Ваше устройство → зашифрованный туннель WireGuard → VPS → Интернет

Сайты видят публичный IP VPS, а не IP домашнего или мобильного провайдера.
```

VPN не делает пользователя «невидимым»: сервисы по-прежнему могут узнавать вас по учётной записи, cookies, отпечатку браузера и другим данным. Геолокация по IP приблизительна и зависит от базы данных конкретного сайта.

## Шаг 1. Создайте VPS

В панели облачного провайдера создайте виртуальный сервер:

- ОС: Ubuntu 24.04 LTS либо Debian 12.
- Сеть: выделенный публичный IPv4.
- Доступ: добавьте свой SSH-ключ; пароль root лучше не использовать.
- Firewall/security group: разрешите `TCP 22` для SSH и `UDP 51820` для WireGuard.

Сохраните два значения из панели: публичный IP VPS и данные для первого SSH-подключения.

---

## Шаг 2. Подключитесь по SSH

Linux, macOS или Windows PowerShell с OpenSSH:

```bash

ssh root@<VPS_PUBLIC_IP>
```

Если ключ расположен не в стандартном месте:

```bash

ssh -i ~/.ssh/id_ed25519 root@<VPS_PUBLIC_IP>
```

После первого входа обновите систему:

```bash

apt update && apt upgrade -y
```

Задайте понятное имя сервера, чтобы его было легче узнавать в SSH и логах:

```bash

hostnamectl set-hostname vpn-server
```

Замените `vpn-server` на своё имя. Используйте только строчные латинские буквы, цифры и дефис.

Проверьте, что имя применилось:

```bash

hostname
hostnamectl status
```

Новое имя появится в приглашении командной строки после переподключения по SSH.

Проверьте имя внешнего интерфейса. Оно понадобится для NAT; часто это `eth0`, `ens3` или `enp1s0`.

```bash

ip route get 1.1.1.1
```

В выводе найдите значение после `dev`, например `ens3`.

---

## Шаг 3. Установите WireGuard

```bash

apt install -y wireguard wireguard-tools qrencode
modprobe wireguard
```

Убедитесь, что модуль загружен:

```bash

lsmod | grep wireguard
```

---

## Шаг 4. Сгенерируйте ключи

Создайте защищённый каталог и ключи сервера и первого клиента:

```bash

install -d -m 700 /etc/wireguard
cd /etc/wireguard

wg genkey | tee server_private.key | wg pubkey > server_public.key
wg genkey | tee client1_private.key | wg pubkey > client1_public.key

chmod 600 *_private.key
```

Посмотреть значения можно так:

```bash

cat server_private.key
cat server_public.key
cat client1_private.key
cat client1_public.key
```

Никому не передавайте приватные ключи. Для каждого устройства создавайте отдельную пару ключей.

---

## Шаг 5. Включите маршрутизацию

Включите пересылку IPv4-пакетов между VPN-интерфейсом и внешней сетью:

```bash

cat > /etc/sysctl.d/99-wireguard.conf <<'EOF'
net.ipv4.ip_forward = 1
EOF

sysctl --system
```

Проверьте результат:

```bash

sysctl net.ipv4.ip_forward
```

Ожидаемое значение: `net.ipv4.ip_forward = 1`.

---

## Шаг 6. Настройте сервер

Подставьте значения ключей и имя внешнего интерфейса. В примере ниже внешний интерфейс — `ens3`; замените его на найденное в шаге 2 имя.

```bash

SERVER_PRIVATE_KEY=$(cat /etc/wireguard/server_private.key)
CLIENT1_PUBLIC_KEY=$(cat /etc/wireguard/client1_public.key)
WAN_IF=ens3

cat > /etc/wireguard/wg0.conf <<EOF
[Interface]
PrivateKey = $SERVER_PRIVATE_KEY
Address = 10.66.0.1/24
ListenPort = 51820
PostUp = iptables -A FORWARD -i %i -j ACCEPT; iptables -A FORWARD -o %i -j ACCEPT; iptables -t nat -A POSTROUTING -o $WAN_IF -j MASQUERADE
PostDown = iptables -D FORWARD -i %i -j ACCEPT; iptables -D FORWARD -o %i -j ACCEPT; iptables -t nat -D POSTROUTING -o $WAN_IF -j MASQUERADE

[Peer]
# client1
PublicKey = $CLIENT1_PUBLIC_KEY
AllowedIPs = 10.66.0.2/32
EOF

chmod 600 /etc/wireguard/wg0.conf
```

Проверьте файл:

```bash

cat /etc/wireguard/wg0.conf
```

Если на сервере уже настроен сложный firewall, Docker, Kubernetes или собственные правила NAT, не добавляйте правила вслепую: сначала проверьте существующие цепочки `iptables -S` и `iptables -t nat -S`.

---

## Шаг 7. Откройте порт

В панели VPS-провайдера откройте входящий `UDP 51820`. Это обязательный отдельный шаг: UFW на сервере не заменяет cloud firewall/security group.

Если используете UFW на сервере:

```bash

ufw allow OpenSSH
ufw allow 51820/udp
ufw enable
ufw status verbose
```

Если UFW уже включён, достаточно выполнить первые две команды.

---

## Шаг 8. Запустите VPN

```bash

systemctl enable --now wg-quick@wg0
wg show
ip address show wg0
```

У интерфейса `wg0` должен быть адрес `10.66.0.1/24`. В `wg show` пока не будет `latest handshake`: он появится только после первого подключения клиента.

Для просмотра журнала службы:

```bash

journalctl -u wg-quick@wg0 -b --no-pager
```

## Шаг 9. Подготовьте конфигурацию клиента

На VPS создайте файл первого клиента. Замените `<VPS_PUBLIC_IP>` на публичный IP вашего сервера или доменное имя.

```bash

CLIENT1_PRIVATE_KEY=$(cat /etc/wireguard/client1_private.key)
SERVER_PUBLIC_KEY=$(cat /etc/wireguard/server_public.key)

cat > /root/client1.conf <<EOF
[Interface]
PrivateKey = $CLIENT1_PRIVATE_KEY
Address = 10.66.0.2/24
DNS = 1.1.1.1

[Peer]
PublicKey = $SERVER_PUBLIC_KEY
Endpoint = <VPS_PUBLIC_IP>:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
EOF

chmod 600 /root/client1.conf
```

Параметр `AllowedIPs = 0.0.0.0/0` отправляет через VPN весь IPv4-трафик. `PersistentKeepalive = 25` помогает устройствам за NAT поддерживать доступность туннеля.

Посмотрите конфигурацию перед импортом:

```bash

cat /root/client1.conf
```

Передать файл на ПК можно через `scp`:

```bash

scp root@<VPS_PUBLIC_IP>:/root/client1.conf ./client1.conf
```

Не отправляйте этот файл в мессенджеры, публичные репозитории и облачные папки без шифрования: внутри находится приватный ключ устройства.

## Шаг 10. Установите приложение-клиент

### Windows

Установите официальный WireGuard for Windows: https://www.wireguard.com/install/

После установки откройте приложение, нажмите **Add Tunnel** → **Import tunnel(s) from file**, выберите `client1.conf`, затем нажмите **Activate**. Приложение показывает статус туннеля, объём переданных данных и время последнего рукопожатия.

### Android

Установите приложение **WireGuard** из Google Play или F-Droid. Официальные ссылки: https://www.wireguard.com/install/

В приложении нажмите `+`, выберите **Create from file or archive** и импортируйте `client1.conf`. Для импорта по QR-коду на VPS выполните:

```bash

qrencode -t ansiutf8 < /root/client1.conf
```

В Android WireGuard выберите добавление туннеля через QR-код и отсканируйте его. Не показывайте QR-код посторонним: он содержит приватный ключ.

### iPhone и iPad

Установите официальное приложение WireGuard из App Store: https://apps.apple.com/app/wireguard/id1441195209

Откройте приложение, выберите добавление туннеля, затем **Create from QR code** или импортируйте файл `client1.conf`. После импорта включайте VPN переключателем рядом с именем туннеля.

### macOS

Установите WireGuard из Mac App Store: https://apps.apple.com/app/wireguard/id1451685025

Импортируйте `client1.conf` через пункт **Import tunnel(s) from file**, затем активируйте туннель. После подключения в строке меню macOS появится системный индикатор VPN.

### Linux

Для Ubuntu/Debian установите клиент:

```bash

sudo apt update
sudo apt install -y wireguard-tools
```

Скопируйте файл в `/etc/wireguard/` и поднимите туннель:

```bash

sudo install -m 600 client1.conf /etc/wireguard/wg0.conf
sudo wg-quick up wg0
```

Отключение:

```bash

sudo wg-quick down wg0
```

Для графического управления можно импортировать конфигурацию в NetworkManager, если дистрибутив и окружение рабочего стола поддерживают WireGuard.

## Шаг 11. Подключитесь к VPN

1. Импортируйте файл `client1.conf` в приложение WireGuard.
2. Нажмите **Activate**, **Connect** или включите переключатель туннеля.
3. Подождите 5–15 секунд.
4. На VPS выполните команду:

```bash

wg show
```

Ищите у peer строки `latest handshake` с недавним временем и увеличивающиеся значения `transfer`. Это означает, что клиент успешно установил туннель и передаёт данные.

Для мобильных сетей и публичного Wi-Fi параметр `PersistentKeepalive = 25` в конфигурации клиента особенно полезен.

## Шаг 12. Проверьте IP, геолокацию и утечки

Проверять VPN лучше в двух состояниях: сначала отключите туннель и зафиксируйте исходные значения, затем включите VPN и повторите те же проверки.

### Официальный WireGuard и другие клиенты

Официальные клиенты WireGuard из шага 10 **только поднимают туннель**: статус, объём трафика, время последнего handshake. **Встроенной проверки IP, геолокации, DNS или WebRTC в них нет.**

Для self-hosted конфигурации (`client1.conf` из этой инструкции) есть альтернативы с диагностикой. Полностью заменить браузерные тесты (особенно WebRTC) **ни один клиент не может**, но IP и DNS можно проверить, не открывая сайты вручную.

**WireGuide** (Windows, macOS) — ближе всего к «всё в одном» на ПК:

- импортирует `client1.conf`;
- встроенный **DNS leak test** и просмотр таблицы маршрутов;
- kill switch и мониторинг маршрутов;
- open source: https://github.com/korjwl1/wireguide/releases

После подключения туннеля откройте раздел **Diagnostics** и запустите DNS leak test. Внешний IP и DNS должны относиться к VPS, а не к домашнему провайдеру.

**WG Tunnel** (Android) — альтернатива официальному WireGuard:

- импортирует обычные `.conf`-файлы WireGuard;
- режим **Lockdown** — kill switch, блокирует трафик при обрыве туннеля;
- мониторинг handshake в реальном времени;
- open source: https://github.com/wgtunnel/wgtunnel

Внутри приложения нет полноценного теста как на ipleak.net, зато Lockdown снижает риск утечки при падении VPN.

**Tunneld** (Android) — отдельное privacy-приложение, не VPN-клиент:

- отслеживает смену IP и делает DNS leak test;
- ведёт историю проверок локально, без трекеров;
- https://github.com/chmikiro/tunneld

Схема: подключите VPN в WireGuard или WG Tunnel → откройте Tunneld → проверьте IP и DNS.

**Vortix** (Linux, macOS, терминал) — для тех, кто работает в консоли:

- показывает exit IP с геолокацией;
- мониторит DNS- и IPv6-утечки в реальном времени;
- kill switch через системный firewall;
- https://github.com/Munstar0s/vortix

На **iPhone/iPad** по сути доступен только официальный WireGuard; встроенных leak-тестов для self-hosted конфигурации в App Store почти нет — IP и DNS проверяйте через Safari или терминал на компьютере.

Коммерческие VPN-приложения (Mullvad, Proton VPN, IVPN и др.) иногда показывают «Connection check», но работают **только со своими серверами**, а не с вашим VPS и файлом `client1.conf`.

### Проверка без браузера

#### WireGuide (Windows, macOS)

1. Импортируйте `client1.conf` и подключите туннель.
2. Откройте **Diagnostics** → **DNS leak test**.
3. Убедитесь, что DNS и маршруты не указывают на домашнего провайдера.

#### Tunneld (Android)

1. Подключите VPN в WireGuard или WG Tunnel.
2. Запустите в Tunneld проверку IP и DNS leak test.
3. Сравните результат с отключённым VPN.

#### Терминал (Windows PowerShell, macOS, Linux)

```bash

curl https://api.ipify.org && echo
curl https://ipinfo.io/json
```

Запустите команды до и после включения VPN. При работающем туннеле первая команда должна возвращать публичный IP VPS.

### Полная проверка в браузере

Браузер всё ещё нужен для WebRTC и комплексной проверки «как видит вас сайт». Откройте один из сервисов:

- https://ipleak.net — показывает внешний IP, предполагаемую геолокацию, DNS и возможные WebRTC-утечки.
- https://browserleaks.com/ip — показывает IP-адреса, видимые браузеру.
- https://whoer.net — показывает публичный IP, сведения о сети и VPN-проверку.
- https://ipinfo.io — быстро показывает публичный IP, организацию и ориентировочную геолокацию.

При включённом VPN внешний IP должен совпадать с публичным IP VPS. Страна и город должны соответствовать данным, которые геолокационная база относит к IP VPS; точность города не гарантирована.

### Проверка DNS в реальном времени

Откройте https://www.dnsleaktest.com/ и запустите **Standard test**, затем при необходимости **Extended test**.

При включённом VPN в списке не должны появляться DNS-серверы вашего домашнего или мобильного интернет-провайдера. В текущей базовой конфигурации используется DNS `1.1.1.1`, поэтому в тесте могут отображаться DNS Cloudflare; это нормально, если ваш реальный IP и DNS провайдера не раскрываются.

### Проверка WebRTC

Откройте https://browserleaks.com/webrtc или раздел WebRTC на https://ipleak.net.

Если сервис показывает публичный IP вашего провайдера при активном VPN, это утечка. В таком случае отключите WebRTC в браузере либо используйте браузерное расширение/настройки, блокирующие WebRTC-утечки, и повторите тест.

### Проверка IPv6

Откройте https://test-ipv6.com/.

В этом документе настроен IPv4-туннель. Если провайдер выдаёт вашему устройству IPv6, часть трафика потенциально может пройти вне IPv4 VPN-туннеля. Для надёжности либо добавьте полноценную IPv6-конфигурацию WireGuard, либо временно отключите IPv6 на клиентском устройстве и повторите IP/DNS-тесты.

### Автоматическая регулярная проверка

На ПК удобно держать открытым WireGuide с подключённым туннелем: после смены сети смотрите статус и при необходимости повторяйте DNS leak test. На Android — Tunneld с историей IP. В браузере можно оставить вкладку https://ipleak.net или https://whoer.net: после переподключения обновите страницу и сразу увидите текущий внешний IP и приблизительную локацию.

## Проверка с сервера

Основная команда администратора:

```bash

wg show
```

Что означает вывод:

- `latest handshake: ... ago` — клиент недавно связался с сервером.
- `transfer: ... received, ... sent` — через туннель реально идут данные.
- Нет `latest handshake` — клиент не достучался до сервера, проверьте endpoint, UDP-порт 51820 и firewall.

Наблюдать за состоянием в реальном времени:

```bash

watch -n 2 wg show
```

Проверить, слушает ли VPS UDP-порт:

```bash

ss -lunp | grep 51820
```

## Добавление устройств

Для каждого нового телефона или компьютера создавайте собственные ключи и отдельный адрес в VPN-подсети. Не копируйте `client1.conf` на несколько устройств.

Пример для второго клиента с адресом `10.66.0.3`:

```bash

cd /etc/wireguard
wg genkey | tee client2_private.key | wg pubkey > client2_public.key
chmod 600 client2_private.key

CLIENT2_PUBLIC_KEY=$(cat client2_public.key)
cat >> /etc/wireguard/wg0.conf <<EOF

[Peer]
# client2
PublicKey = $CLIENT2_PUBLIC_KEY
AllowedIPs = 10.66.0.3/32
EOF

wg syncconf wg0 <(wg-quick strip wg0)
```

Создайте `/root/client2.conf`, заменив приватный ключ на содержимое `client2_private.key` и адрес на `10.66.0.3/24`:

```ini

[Interface]
PrivateKey = <CLIENT2_PRIVATE_KEY>
Address = 10.66.0.3/24
DNS = 1.1.1.1

[Peer]
PublicKey = <SERVER_PUBLIC_KEY>
Endpoint = <VPS_PUBLIC_IP>:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Если устройство утеряно, удалите соответствующий блок `[Peer]` из `/etc/wireguard/wg0.conf` и примените конфигурацию:

```bash

wg syncconf wg0 <(wg-quick strip wg0)
```

## Несколько VPS в разных локациях

Нужен выход в интернет из разных стран — арендуете **несколько VPS** (у одного или разных провайдеров). На **каждом** VPS ставите WireGuard. На **телефоне** — несколько записей; переключение между странами — выключить одну, включить другую.

**Приватные ключи никуда в облако (Google Drive, Dropbox и т.п.) не кладут.** Они живут только на VPS и на вашем устройстве.
### Какие ключи вообще есть

В WireGuard участвуют **две стороны** — сервер (VPS) и клиент (ваш телефон). У каждой стороны своя пара ключей. Всё это создаётся **один раз** в шаге 4 на **первом** VPS:

| Кто | Файлы на VPS (шаг 4) | Где используется |
|-----|----------------------|------------------|
| **Сервер** | `server_private.key`, `server_public.key` | в `wg0.conf` на VPS |
| **Ваш телефон** | `client1_private.key`, `client1_public.key` | приватный — в `client1.conf` на телефоне; публичный — в `wg0.conf` на VPS как peer |

**Публичный ключ** можно показывать кому угодно — это «адрес» стороны. **Приватный ключ** — секрет: только на VPS или только на телефоне.

Для нескольких стран **новые ключи не создают**. Используют **те же самые**, что получились в шаге 4 на первом VPS.

### Что меняется от страны к стране

| | Первый VPS (DE) | Второй VPS (FI) | Телефон |
|---|-----------------|-----------------|---------|
| IP сервера | свой | свой | в конфиге — строка `Endpoint` |
| Файлы ключей сервера | из шага 4 | **те же файлы**, скопированные с первого VPS | не меняются |
| Ключ телефона | тот же peer | тот же peer | один `PrivateKey` во всех конфигах |

На телефоне конфиги **почти одинаковые**. Отличается **только** `Endpoint` — IP-адрес VPS в нужной стране:

```ini

[Interface]
PrivateKey = ...ваш ключ телефона, везде один...
Address = 10.66.0.2/24
DNS = 1.1.1.1

[Peer]
PublicKey = ...ключ сервера, везде один...
Endpoint = 203.0.113.10:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Для Финляндии копируете этот файл, меняете **одну строку** `Endpoint` на IP финского VPS и импортируете как вторую запись.

### Первый VPS

Настраиваете по шагам 1–9 — как описано выше. В шаге 4 появляются все ключи. Запомните IP этого VPS — он пойдёт в `Endpoint` для первой страны.

### Второй и следующие VPS

1. Арендуете VPS в другой стране.
2. По SSH: обновление системы, установка WireGuard (шаги 2–3).
3. **Копируете с первого VPS** уже готовые файлы — **не** запускаете шаг 4 заново:

```bash

# Выполняете на своём ПК. Замените IP_DE и IP_FI на реальные адреса VPS.

scp root@IP_DE:/etc/wireguard/server_private.key root@IP_FI:/etc/wireguard/
scp root@IP_DE:/etc/wireguard/server_public.key  root@IP_FI:/etc/wireguard/
scp root@IP_DE:/etc/wireguard/wg0.conf           root@IP_FI:/etc/wireguard/

ssh root@IP_FI 'install -d -m 700 /etc/wireguard && chmod 600 /etc/wireguard/*_private.key /etc/wireguard/wg0.conf'
```

4. На новом VPS проверьте имя сетевого интерфейса (`ip route get 1.1.1.1`). Если не `ens3` — поправьте его в `PostUp`/`PostDown` внутри `wg0.conf`.
5. Маршрутизация, firewall, запуск VPN (шаги 5–8).

На втором VPS лежат **те же** файлы ключей сервера, что на первом — вы их **перенесли** с первого VPS, а не создали заново.

### Записи на телефоне

| Файл | Имя в WireGuard | Единственное отличие |
|------|-----------------|----------------------|
| `wg-de.conf` | Германия | `Endpoint = IP_DE:51820` |
| `wg-fi.conf` | Финляндия | `Endpoint = IP_FI:51820` |

Импортируйте оба файла в WireGuard, WireGuide или WG Tunnel.

### Как переключаться между локациями

**Официальный WireGuard (Windows, macOS, Android, iOS):**

1. Отключите текущий активный туннель.
2. Включите нужный (например, **FI Helsinki**).
3. Подождите 5–15 секунд и проверьте IP (шаг 12).

Одновременно держать два туннеля с `AllowedIPs = 0.0.0.0/0` нельзя — маршруты конфликтуют. В каждый момент времени активна **одна** локация.

**WireGuide (Windows, macOS):** импортируйте все `.conf`, переключайтесь одним кликом в списке туннелей.

**Linux (`wg-quick`):**

```bash

sudo wg-quick down wg-de
sudo wg-quick up wg-fi
```

### Передача конфигов на телефон

Возьмите `client1.conf` с первого VPS. Сделайте копию, в копии поменяйте только `Endpoint` на IP второго VPS. Импортируйте оба файла.

QR-код для Android:

```bash

qrencode -t ansiutf8 < wg-fi.conf
```

### Проверка после переключения

После смены локации убедитесь, что внешний IP изменился на IP **нового** VPS:

```bash

curl https://api.ipify.org && echo
curl https://ipinfo.io/json
```

Страна и город в ответе должны соответствовать региону выбранного сервера.

### Краткий чеклист

- [ ] Ключи созданы **один раз** — в шаге 4 на первом VPS.
- [ ] На второй VPS файлы **скопированы с первого** через `scp`, шаг 4 там **не повторяли**.
- [ ] На телефоне — несколько конфигов; в каждом свой `Endpoint`, остальное одинаково.
- [ ] Приватные ключи **не** лежат в Google Drive / Dropbox / мессенджерах.

## Повседневное использование

- Включайте туннель в приложении WireGuard перед работой через VPN; выключайте, когда он не нужен.
- При смене Wi-Fi на мобильную сеть WireGuard обычно переподключается сам. Если нет — выключите и снова включите туннель.
- Для полного туннелирования оставляйте `AllowedIPs = 0.0.0.0/0`.
- Проверяйте внешний IP после первой настройки, после изменения конфигурации и при подозрении на проблемы через https://ipleak.net.
- Периодически обновляйте сервер: `apt update && apt upgrade -y`.

## Диагностика

### Приложение подключено, но интернета нет

Проверьте:

```bash

sysctl net.ipv4.ip_forward
wg show
ip route get 1.1.1.1
iptables -t nat -S POSTROUTING
```

Частая причина — неверное имя внешнего интерфейса в `PostUp` и `PostDown`. Замените `ens3` на фактическое имя, затем перезапустите:

```bash

systemctl restart wg-quick@wg0
```

### Нет handshake

Проверьте следующее:

- Указан верный `Endpoint = <IP_VPS>:51820`.
- В панели провайдера открыт `UDP 51820`.
- UFW разрешает `51820/udp`.
- Публичный IP VPS не изменился.
- Время на сервере корректно: `timedatectl status`.

### IP изменился, но DNS показывает провайдера

Проверьте `DNS = 1.1.1.1` в конфигурации клиента, переподключите туннель и выполните Extended test на https://www.dnsleaktest.com/. Если проблема остаётся, проверьте настройки DNS в ОС, корпоративные агенты безопасности и браузерный DNS-over-HTTPS.

### Виден реальный IPv6

Настройте IPv6 в WireGuard либо временно отключите IPv6 на устройстве. Затем повторите проверку на https://test-ipv6.com/ и https://ipleak.net.

## Безопасность

- Используйте SSH-ключи и отключите парольный вход root после того, как убедились в доступе по ключу.
- Не публикуйте `client*.conf`, приватные ключи, QR-коды и резервные копии `/etc/wireguard`.
- Для каждого устройства используйте отдельный peer и отдельный адрес.
- После потери телефона/ноутбука немедленно удаляйте его peer на сервере.
- Ограничьте SSH в cloud firewall собственными IP, если у вас есть статичный доверенный адрес.
- Храните резервную копию конфигурации сервера в зашифрованном хранилище.

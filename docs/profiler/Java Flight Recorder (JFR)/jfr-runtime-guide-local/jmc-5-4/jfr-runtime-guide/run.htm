2 Запуск Java Flight Recorder

В этой главе описывается, как запускать Java Flight Recorder.

Примечание:

Для использования Java Flight Recorder в производственной среде требуется коммерческая лицензия. Подробнее о коммерческих функциях и о том, как их включить, см. по адресу http://www.oracle.com/technetwork/java/javaseproducts/.

Можно одновременно выполнять несколько записей (recordings) и настраивать каждую запись с помощью различных параметров; в частности, разные записи можно настроить на захват разных наборов событий. Однако, чтобы внутренняя логика Java Flight Recorder была как можно более простой, итоговая запись всегда содержит объединение всех событий всех записей, активных в данный момент. Это означает, что если выполняется более одной записи, в ней может оказаться больше сведений, чем требовалось. Это может вызывать путаницу, но иных отрицательных последствий не имеет.

Самый простой и наглядный способ использовать JFR (Java Flight Recorder, журнал полёта Java) — через плагин Flight Recorder, встроенный в Java Mission Control. Этот плагин открывает доступ к возможностям JFR через наглядный GUI. Подробнее об управлении JFR с помощью клиента JMC (Java Mission Control) см. в разделе о плагине Flight Recorder справки Java Mission Control.

В этой главе рассматриваются более сложные способы запуска и управления записями JFR и содержатся следующие разделы:

  • Использование командной строки

  • Использование диагностических команд

  • Настройка записей

  • Автоматическое создание записей

  • Безопасность

  • Устранение неполадок

2.1 Использование командной строки

Запись можно запустить и настроить из командной строки с помощью параметра -XX:StartFlightRecording команды java при запуске приложения. Чтобы разрешить использование JFR, укажите параметр -XX:+FlightRecorder. Поскольку JFR является коммерческой функцией, необходимо также указать параметр -XX:+UnlockCommercialFeatures. В следующем примере показано, как запустить приложение MyApp и сразу начать 60-секундную запись, которая будет сохранена в файл с именем myrecording.jfr:

java -XX:+UnlockCommercialFeatures -XX:+FlightRecorder -XX:StartFlightRecording=duration=60s,filename=myrecording.jfr MyApp

Для настройки JFR можно использовать параметр -XX:FlightRecorderOptions. Подробнее см. в приложении A, «Параметры командной строки».

2.2 Использование диагностических команд

Записями также можно управлять с помощью диагностических команд (diagnostic commands), специфичных для Java. Более подробное описание диагностических команд см. в приложении A, «Справочник диагностических команд».

Простейший способ выполнить диагностическую команду — использовать средство jcmd (оно находится в каталоге установки Java). Чтобы выдать команду, необходимо передать идентификатор процесса JVM (Java Virtual Machine, виртуальная машина Java) (или имя главного класса) и саму команду в качестве аргументов jcmd. Например, чтобы начать 60-секундную запись для выполняющегося процесса Java с идентификатором 5368 и сохранить её в файл myrecording.jfr в текущем каталоге, используйте следующее:

jcmd 5368 JFR.start duration=60s filename=myrecording.jfr

Чтобы увидеть список всех выполняющихся процессов Java, выполните команду jcmd без аргументов. Чтобы увидеть полный список команд, доступных выполняющемуся приложению Java, укажите help в качестве диагностической команды после идентификатора процесса (или имени главного класса). Команды, относящиеся к Java Flight Recorder:

  • JFR.start

    Начать запись.

  • JFR.check

    Проверить состояние всех записей, выполняющихся для указанного процесса, включая идентификационный номер записи, имя файла, длительность и так далее.

  • JFR.stop

    Остановить запись с заданным идентификационным номером (по умолчанию останавливается запись 1).

  • JFR.dump

    Выгрузить данные, собранные к текущему моменту записью с заданным идентификационным номером (по умолчанию выгружаются данные записи 1).

Примечание:

Эти команды доступны, только если приложение Java было запущено с включённым Java Flight Recorder, то есть со следующими параметрами: 
-XX:+UnlockCommercialFeatures -XX:+FlightRecorder

2.3 Настройка записей

Явную запись можно настроить и другими способами. Эти приёмы работают одинаково независимо от того, как запускается запись (то есть с помощью командной строки или диагностических команд).

2.3.1 Задание максимального размера и возраста

Для явной записи можно задать максимальный размер или возраст с помощью следующих параметров:

  • maxsize=size

    Добавьте букву k или K для килобайтов, m или M для мегабайтов, g или G для гигабайтов либо не указывайте суффикс, чтобы задать размер в байтах.

  • maxage=age

    Добавьте букву s для секунд, m для минут, h для часов или d для суток.

Если заданы и ограничение размера, и возраст, данные удаляются при достижении любого из пределов.

2.3.2 Задание задержки

При планировании записи может потребоваться добавить задержку (delay) перед фактическим началом записи; например, при запуске из командной строки может быть нужно, чтобы приложение загрузилось или вышло на установившийся режим до начала записи. Для этого используйте параметр delay:

delay=delay

Добавьте букву s для секунд, m для минут, h для часов или d для суток.

2.3.3 Задание сжатия

Хотя формат файла записи весьма компактен, его можно дополнительно сжать, поместив в архив ZIP. Чтобы включить сжатие, используйте следующий параметр:

compress=true

Учтите, что для сжатия требуются ресурсы CPU, что может отрицательно сказаться на производительности.

2.4 Автоматическое создание записей

При работе с записью по умолчанию (default recording) можно настроить Java Flight Recorder так, чтобы текущие данные записи из памяти автоматически сохранялись в файл при наступлении определённых условий. Если используется дисковое хранилище, в файл также будут включены текущие сведения из дискового хранилища.

2.4.1 Создание записи при выходе

Чтобы сохранять данные записи по указанному пути каждый раз при выходе JVM, запустите приложение со следующим параметром:

-XX:FlightRecorderOptions=defaultrecording=true,dumponexit=true,dumponexitpath=path

Задайте в path расположение, в котором следует сохранить запись. Если указать каталог, в нём будет создан файл с именем из даты и времени. Если указать имя файла, будет использовано это имя. Если путь не указан, запись будет сохранена в текущем каталоге.

2.4.2 Создание записи с помощью триггеров (triggers)

В консоли Java Mission Control можно задавать триггеры (triggers). Триггер (trigger) — это правило, которое выполняет действие всякий раз, когда истинно указанное в правиле условие. Например, можно создать правило, которое запускает запись полёта, когда размер кучи превышает 100 МБ. Триггеры в Java Mission Control могут использовать в качестве входных данных правила любое свойство, предоставляемое через JMX MBeans. Они могут запускать и многие другие действия, а не только дампы Flight Recorder.

Триггеры задаются на вкладке Triggers (триггеры) в JMX Console (консоль JMX). Подробнее о создании триггеров см. в справке Java Mission Control.

2.5 Безопасность

Java Flight Recorder предназначен только для диагностических целей. Файл записи потенциально может содержать конфиденциальные сведения, например параметры командной строки Java и переменные среды. Храните и передавайте файлы записей с такой же осторожностью, как диагностические файлы дампа ядра (core files) или снимки кучи (heap dumps).

Таблица 2-1 описывает разрешения безопасности для различных способов использования JFR.

«Таблица 2-1. Разрешения безопасности»

Метод Безопасность

Командная строка

Любой, у кого есть доступ к командной строке процесса Java, должен быть доверенным лицом.

Диагностические команды

Управлять процессом с помощью jcmd может только владелец процесса Java.

Клиент Java Mission Control

Клиент Java Mission Control использует JMX для доступа к JVM.

2.6 Устранение неполадок

Значительный объём диагностических сведений из Java Flight Recorder можно получить, запустив JVM с одним из следующих параметров:

  • -XX:FlightRecorderOptions=loglevel=debug

  • -XX:FlightRecorderOptions=loglevel=trace.

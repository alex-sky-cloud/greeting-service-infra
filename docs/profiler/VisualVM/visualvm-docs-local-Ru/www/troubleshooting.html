Руководство по устранению неполадок VisualVM

В этом документе описаны самые частые проблемы при использовании VisualVM и сведения, как их исправить или обойти. Если проблема не описана здесь, обратитесь за помощью в mailing list (список рассылки) или file a bug report (отправьте отчёт об ошибке) (чтобы пользоваться списком рассылки или отправлять отчёты об ошибках, нужно зарегистрироваться).

Проблемы с запуском VisualVM

VisualVM Does Not Start

Описание: VisualVM вообще не запускается без видимой причины.

Решение:  есть несколько причин, из-за которых VisualVM может не запуститься:

  • The download is broken — убедитесь, что получили правильные файлы (менеджеры архивов обычно сообщают, если архив повреждён)
  • VisualVM waits for license confirmation — убедитесь, что не пропустили диалог License Agreement (лицензионное соглашение)
  • Incorrect JDK is used for running VisualVM — если вы не задали JDK (Java Development Kit, комплект разработки Java) для запуска VisualVM вручную, убедитесь, что Java по умолчанию в системе — Oracle/Sun JDK 7+ (или JDK 6+ для VisualVM 1.3.6 и более ранних версий)
  • Incorrectly set JDK for running VisualVM — если вы задали JDK для запуска VisualVM вручную, убедитесь, что путь к JDK правильный и не заканчивается слэшем
  • Incorrectly set VisualVM user directory — если вы задали каталог пользователя VisualVM вручную, убедитесь, что он находится вне каталога установки VisualVM

VisualVM has stopped working (Native Error Dialog During Startup)

Описание: во время запуска VisualVM операционная система показывает диалог 'VisualVM has stopped working', процесс VisualVM завершается.

Решение:  эта проблема возникает в системах Windows, когда процесс VisualVM запущен в Compatibility mode для Windows 95/98/ME. Убедитесь, что Compatibility mode отключён для запускателя VisualVM, или при необходимости используйте Compatibility mode для самой новой возможной версии ОС. Примечание: запускать VisualVM или наблюдаемые приложения Java в Compatibility mode настоятельно не рекомендуется: несовместимости виртуализированных сред могут аварийно завершать процессы Java.


Java(TM) Platform SE binary has stopped working (Native Error Dialog During Startup)

Описание: во время запуска VisualVM операционная система показывает диалог 'Java(TM) Platform SE binary has stopped working', процесс VisualVM завершается.

Решение:  это известная ошибка JDK в конвейере отрисовки d3d, затрагивающая 64-разрядные системы Windows. Чтобы отключить ускорение d3d, запускайте VisualVM командой visualvm.exe -J-Dsun.java2d.d3d=false. Либо обновите файл <visualvm_installdir>\etc\visualvm.conf, чтобы включить переключатель -J-Dsun.java2d.d3d=false в раздел default_options. Подробности см. в JDK bug #6772139 (ошибка JDK №6772139).


Error Starting VisualVM (Error Dialog During Startup)

Описание: во время запуска VisualVM показывается диалог 'Error Starting VisualVM' с сообщением о неподдерживаемой версии Java.

Решение:  VisualVM работает только на JDK 7+ (или JDK 6+ для VisualVM 1.3.6 и более ранних версий) — не на JRE! Если запустить на JRE или неверной версии JDK, VisualVM показывает этот диалог и завершается. Чтобы задать, какой JDK будет использоваться для запуска VisualVM, следуйте шагам в разделе Starting VisualVM документа Getting Started with VisualVM (начало работы с VisualVM).


Warning - could not install some modules (Error Dialog During Startup)

Описание: во время запуска VisualVM показывается диалог 'Warning - could not install some modules' со списком затронутых модулей.

Решение:  обычно так бывает, если распаковать новую версию VisualVM поверх уже существующей установки VisualVM. Распаковывайте VisualVM в новый каталог.


Проблемы при использовании VisualVM

No Running Applications Detected, Exception Thrown After Startup

Описание: в дереве Applications (Приложения) не показаны работающие приложения, после запуска VisualVM выбрасывается исключение (java.lang.NullPointerException at JvmJvmstatModelProvider.createModelFor(JvmJvmstatModelProvider)).

Решение:  так бывает для VisualVM 1.1 и более ранних выпусков и для Java VisualVM 6u11 и более ранних выпусков, когда в системе работает хотя бы одно приложение Java на JDK 6 Update 12 (включая сам VisualVM). Чтобы исправить проблему, скачайте и установите последний плагин VisualVM-Extensions из Plugin Center через Tools (Инструменты) → Plugins (плагины). Подробности в this blog post (этой записи блога).


Local Applications Cannot Be Detected (Error Dialog On Startup)

Описание: сразу после запуска VisualVM показывается диалог ошибки о том, что локальные приложения не могут быть обнаружены.

Решение:  так может случиться в системах Windows; причина — неправильно настроенная технология jvmstat, которая используется для обнаружения работающих приложений. Есть две возможные причины:

  • Insufficient permissions for %TMP%\hsperfdata_username folder — убедитесь, что можете создать файл в каталоге, и при необходимости обновите права для полного доступа к папке. Либо просто заново создайте папку — тогда должны автоматически установиться правильные права доступа. Подробности см. в этой ветке forums.sun.com thread.
  • Having %TMP%\hsperfdata_username folder on a FAT disk — по умолчанию jvmstat не работает на дисках FAT из-за ограничений безопасности. Проверку безопасности можно обойти, задав флаг -XX:+PerfBypassFileSystemCheck и для VisualVM, и для наблюдаемого приложения. Подробности см. в JDK bug #5042659 (ошибка JDK №5042659).

Local Applications Cannot Be Monitored (Error Dialog On Startup)

Описание: сразу после запуска VisualVM показывается диалог ошибки о том, что локальные приложения не могут быть под наблюдением. Локально работающие приложения Java отображаются как <Unknown Application> (pid ###).

Решение:  так может случиться в системах Windows, если в имени пользователя есть заглавные буквы. В этом случае имя пользователя — UserName, но каталог jvmstat, созданный JDK, — %TMP%\hsperfdata_username. Чтобы обойти проблему, закройте все приложения Java, удалите каталог %TMP%\hsperfdata_username и создайте новый каталог %TMP%\hsperfdata_UserName.


No Running Remote Applications Detected

Описание: для удалённого узла в окне Applications слева не показаны работающие приложения.

Решение:  убедитесь, что на удалённом узле, который вы хотите мониторить, работает утилита jstatd. Это необходимо, чтобы VisualVM мог обнаруживать и получать доступ к удалённым приложениям Java. Больше сведений о jstatd в документе Working with Remote Applications (работа с удалёнными приложениями).

Известное ограничение: в этом выпуске VisualVM при запуске утилиты jstatd нужно использовать port и rminame по умолчанию, то есть параметры -p и -n не поддерживаются.


Cannot Add Or Edit Hosts On Linux

Описание: добавление удалённого узла и/или вызов Properties для существующего узла выбрасывает java.lang.NullPointerException на Linux/Solaris, новый узел добавить нельзя.

Решение:  так бывает при запуске VisualVM 1.2 или новее на JDK 7 или OpenJDK 6 с GTK LaF. Причина — ошибка JDK, появившаяся в JDK 7 b10. Подробности в VisualVM bug #372 (ошибка VisualVM №372). Быстрый обходной путь — сменить оформление (look'n'feel) командой visualvm --laf Nimbus или visualvm --laf Metal либо запускать VisualVM на Oracle JDK 7.


HeapWalker Throws Exceptions When Switching Views

Описание: переключение видов (Overview/Classes/Instances/OQL Console) в HeapWalker выбрасывает java.lang.IncompatibleClassChangeError, интерфейс не перерисовывается.

Решение:  так бывает при запуске VisualVM на JDK 6 Update 17 и новее с Windows LaF. Подробности и исправление в VisualVM bug #333 (ошибка VisualVM №333). Быстрый обходной путь — сменить оформление командой visualvm.exe --laf Nimbus или visualvm.exe --laf Metal либо запускать VisualVM на JDK 6 Update 16 (или более раннем).


Profiler Tab Shows Warning About Class Sharing, Profiling Does Not Work

Описание: на вкладке Profiler (Профилировщик) в красной рамке показано предупреждение "Class sharing is enabled for this JVM", профилирование CPU (процессора) или Memory аварийно завершает локальные приложения, работающие на JDK 6 Update 6 и более ранних.

Решение:  есть известная проблема с динамическим attach, который используется для профилирования: целевая JVM (Java Virtual Machine, виртуальная машина Java) может аварийно завершиться, если включено совместное использование классов (class sharing). Чтобы запустить приложение без class sharing, передайте аргумент -Xshare:off команде java, запускающей приложение. Больше сведений в JDK bug #6497639 (ошибка JDK №6497639) и JDK bug #6598065 (ошибка JDK №6598065).


CPU Profiling Fails With "Redefinition failed with error 62"

Описание: профилирование CPU на вкладке Profiler или с плагином Startup Profiler завершается ошибкой, VisualVM показывает сообщение "Redefinition failed with error 62".

Решение:  перезапустите приложение с аргументом VM -Xverify:none, чтобы отключить проверку classfile. Чтобы отключить проверку classfile, приложение нужно перезапустить. Проверку нельзя отключить, пока приложение работает.


Profiler Measures Incorrect Performance Results

Описание: результаты профилирования производительности неверны — нулевые или отрицательные времена и т. д.

Решение:  при первом запуске VisualVM выполняется калибровка, чтобы измерить накладные расходы профилирования на локальной системе. Данные калибровки затем используются для точных результатов профилирования. Когда производительность системы меняется, данные калибровки больше не действительны, и результаты профилирования становятся смещёнными. Чтобы заново откалибровать профилировщик, вручную удалите файл данных калибровки <system userdir>/.nbprofiler/machinedata.jdk1X и перезапустите VisualVM — калибровка будет выполнена снова при запуске VisualVM.


Проблемы с плагинами VisualVM

Cannot Download VisualVM Plugins

Описание: вкладка Available Plugins (Доступные плагины) диалога Plugins отключена, плагины скачать нельзя.

Решение:  эта проблема возникает, когда VisualVM не может подключиться к онлайн Plugins Center. Есть несколько причин, из-за которых VisualVM может не получить доступ к Plugins Center: нет интернета, неправильная настройка прокси, прокси блокирует нужный порт, нет сертификата для dev.java.net и т. д. Убедитесь, что интернет работает и вы можете открыть файл дескриптора Plugins Center по адресу, заданному на вкладке Settings (Параметры) диалога Plugins. Если подключение всё равно не устанавливается, плагины можно скачать на другой машине и установить вручную; подробности на странице Plugins Centers (центры плагинов).


Timeout While Installing a Plugin

Описание: диалог Plugin Installer показывает сообщение 'The Plugin Installer found problem timeout of loading <module name>'.

Решение:  так иногда бывает при установке plugin (плагина) из Plugins Center. Плагин не удалось включить в текущем сеансе VisualVM; перезапустите VisualVM, чтобы начать пользоваться плагином.


Validation Warning While Installing a Plugin

Описание: при установке плагина из VisualVM Plugin Center показывается диалог Validation Warning с сообщением Validation failed.

Решение:  так бывает при установке любого плагина из VisualVM Plugin Center. На самом деле плагины действительны и заслуживают доверия: можно просто пропустить диалог и продолжить установку плагина. Проблема вызвана отсутствующим ключом в инструменте VisualVM для распознавания действительности сертификата плагина.


Cannot Get The List Of Web Applications From GlassFish

Описание: открытие подузла "Model" приложения GlassFish зависает с сообщением "Please Wait"

Решение:  так бывает, когда на целевом сервере не разрешён мониторинг веб-приложений. Чтобы включить мониторинг, в консоли администрирования GlassFish перейдите в Application Server/Monitor/Runtime/Configure Monitoring и задайте Web Container в High. Можно также попробовать открыть настройку по этой link (ссылке).


No Servlets Displayed In The Runtime Area Of GlassFish Web Application Tab

Описание: в области runtime вкладки веб-приложения GlassFish не отображаются сервлеты (см. here (здесь))

Решение:  отображаются только сервлеты, для которых есть какая-то статистика. Чтобы сгенерировать статистику, дайте нагрузку на веб-приложение.

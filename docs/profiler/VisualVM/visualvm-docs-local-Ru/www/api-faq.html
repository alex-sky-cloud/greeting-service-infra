Часто задаваемые вопросы разработчика VisualVM

Это FAQ VisualVM, ориентированный на разработчиков. Разработчик в этом контексте означает «человек, пишущий плагины для VisualVM».

Начало работы

Каков текущий статус API VisualVM?

В разработке. Вы можете создавать плагины, но должны понимать, что в ближайшие месяцы обязательно будут несовместимые изменения. Однако все такие изменения будут ясно задокументированы к моменту соответствующего выпуска.

Как начать расширять VisualVM?

Прочитайте «Начало работы с расширением VisualVM», где даны сведения о расширениях VisualVM, показано, как настроить среду, проведён сценарий «Hello World» и дан обзор всех открытых пакетов VisualVM.

Где находится Javadoc VisualVM?

См. http://visualvm.java.net/.

Нужно ли использовать NetBeans IDE, чтобы расширять VisualVM?

Нет. Однако NetBeans IDE предоставляет мастеры и шаблоны для разработки плагинов VisualVM, тогда как в других IDE такой поддержки (пока) нет.

Жизненный цикл

Каков жизненный цикл плагина VisualVM?

Жизнь плагина начинается, когда он устанавливается в VisualVM. Его можно установить через VisualVM Plugin Manager (диспетчер плагинов, доступен из меню Tools (Сервис)) или при запуске из NetBeans IDE.

Точки входа, реализованные в плагине, должны инициализироваться в классе, расширяющем org.openide.modules.ModuleInstall. Они также должны удаляться через этот класс. Инициализация происходит в методе ModuleInstall.restored, удаление — в методе ModuleInstall.uninstalled.

Каждый пример точек расширения VisualVM включает пример инициализации и удаления точек входа, как в документе Getting Started Extending VisualVM.

Что насчёт файла layer.xml?

Если вы уже создавали модули поверх NetBeans Platform, вам знаком файл конфигурации layer.xml. Этот файл используется для инициализации точек входа в NetBeans Platform. Однако API, специфичные для VisualVM, этот подход не используют. Вместо этого они используют класс org.openide.modules.ModuleInstall, как описано выше.

Однако, поскольку VisualVM основан на NetBeans Platform, VisualVM может повторно использовать несколько API NetBeans Platform. Например, VisualVM повторно использует API NetBeans, отвечающие за пункты главного меню и главные панели инструментов и кнопки на них. Поэтому вам понадобится NetBeans Actions API, когда вы захотите добавить новые пункты меню и панели инструментов в VisualVM. NetBeans Actions API использует файл layer.xml, и поэтому в этом случае вы всё же воспользуетесь файлом layer.xml. Однако, если вы используете NetBeans IDE, достаточно мастера «New Action», и тогда мастер заполнит файл layer.xml за вас. Если у вас есть вопросы об API NetBeans Platform, см. NetBeans Developer FAQ.

Источники данных

Что такое DataSource?

Источник данных — основной актор в API VisualVM. Всё, что происходит в VisualVM, происходит в связи с источником данных.

Самый важный источник данных с точки зрения пользователя — Application. Этот источник данных представляет приложения, которые контролируются и управляются в VisualVM. Остальные существующие источники данных существуют для поддержки источника данных Application.

В VisualVM каждый узел в представлении обозревателя (слева от приложения) предоставляется источником данных (и его вспомогательными классами).

Зачем создавать новый DataSource?

Возможно, вы хотите, чтобы пользователь мог контролировать, устранять неполадки или управлять источником данных, для которого VisualVM не предоставляет поддержку «из коробки». По сути VisualVM — просто инструмент отображения данных, поэтому вы можете создать один или несколько следующих источников данных:

  • Photo
  • ShoppingList
  • Task
  • Reminder

Однако VisualVM создан специально для мониторинга, устранения неполадок и управления. Поэтому новые источники данных вы, скорее всего, захотите создать именно для этих целей. В целом необходимость создавать новый источник данных возникает лишь в очень небольшом числе случаев.

Представления

Что такое представление?

Представление в VisualVM состоит из вкладки и одной или нескольких вложенных вкладок, отображаемых в основной области приложения, когда для источника данных в обозревателе выбирается «Open» (Открыть).

  • Вкладка — это, например, «Overview» (Обзор), «Monitor» (Монитор) и «Threads» (Потоки).
  • Вложенная вкладка — это, например, «JVM Arguments» (Аргументы JVM) и «System Properties» (Системные свойства) внутри вкладки «Overview».

Как создавать новые представления (вкладки, подключаемые вкладки, вложенные вкладки)?

Новые вкладки создаются расширением этих классов:

  • com.sun.tools.visualvm.core.ui.DataSourceView
  • com.sun.tools.visualvm.core.ui.DataSourceViewProvider

Полный пример создания новых вкладок можно найти здесь.

Чтобы вкладки можно было расширять, нужно расширить следующий API:

  • com.sun.tools.visualvm.core.ui.PluggableViewSupport

Полный пример создания подключаемого представления можно найти здесь.

Новые вложенные вкладки создаются расширением этих классов:

  • com.sun.tools.visualvm.core.ui.ViewPlugin
  • com.sun.tools.visualvm.core.ui.ViewPlugin.ViewDescriptor

Вложенную вкладку можно добавить к вкладке, только если вкладка создана как подключаемая, то есть только если вкладка использует com.sun.tools.visualvm.core.ui.PluggableViewSupport. В случае предопределённых вкладок VisualVM нужно инициализировать класс поддержки, относящийся к подключаемому представлению, которое вы хотите расширить:

  • com.sun.tools.visualvm.core.dataview.monitor.MonitorViewSupport
  • com.sun.tools.visualvm.core.dataview.overview.OverviewViewSupport
  • com.sun.tools.visualvm.core.dataview.threads.ThreadsViewSupport
  • com.sun.tools.visualvm.core.heapdump.HeapDumpSupport
  • com.sun.tools.visualvm.core.threaddump.ThreadDumpSupport

Полный пример добавления вложенной вкладки на вкладку «Overview» можно найти здесь.

Типы приложений

Что такое тип приложения?

Тип приложения — модель, которую нужно создать, когда вы хотите, чтобы VisualVM обслуживал новый вид приложения. Например, плагин GlassFish создаёт новый тип приложения для приложений, у которых главный класс — com.sun.enterprise.server.PELaunch. Поскольку это главный класс сервера приложений GlassFish, тип приложения создаётся всякий раз, когда запускается экземпляр GlassFish.

Каковы типы приложений по умолчанию?

Ниже перечислены предопределённые типы приложений:

  • DefaultApplicationType
  • JavaPluginApplicationType
  • JavaWebStartApplicationType
  • MainClassApplicationType
  • NetBeans3xApplicationType
  • NetBeansApplicationType
  • NetBeansBasedApplicationType
  • VisualVMApplicationType

Зачем создавать собственные типы приложений?

Собственный тип приложения стоит создать, если у вас есть приложение, которое вы хотите обрабатывать в VisualVM особым образом. По умолчанию для обработки приложения будет использоваться DefaultApplicationType. Однако, если ваше приложение — сервер развёртывания, вы, вероятно, захотите отображать узлы развёрнутых приложений как подоузлы узла приложения в обозревателе. В этом случае нужно смоделировать новый тип приложения и затем создавать его через класс-фабрику. Чаще всего, как в случае GlassFish, фабрика создаёт ваш тип приложения, если у запущенного приложения главный класс совпадает с главным классом, определённым в реализации типа приложения.

Узлы (Hosts)

Что такое узел (host)?

Класс Host предоставляет общий интерфейс для источников данных, представляющих localhost или удалённый узел. Это источник данных, так же как Application — источник данных. Однако для конечного пользователя он не так важен, как источник данных Application. По умолчанию VisualVM предоставляет вкладку для каждого узла, показывая сведения, специфичные для узла, такие как статистика CPU и памяти, а также IP узла и операционную систему.

Включение и отключение функциональности

Как убедиться, что у приложения включён JMX?

Возможно, вы хотите, чтобы представление показывалось, только если включён JMX. Для этого у вас есть два класса:

  • com.sun.tools.visualvm.core.model.jmx.JmxModel
  • com.sun.tools.visualvm.core.model.jmx.JmxModelFactory

Для этих целей используйте DataSourceViewProvider.supportsViewFor так: 

public boolean supportsViewFor(Application application) {
    JmxModel jmx = JmxModelFactory.getJmxModelFor(application);
    MBeanServerConnection mbsc = jmx.getMBeanServerConnection();
    return mbsc != null;
}

Если возвращается false, JMX не включён и представление не будет показано.

Распространение

Как распространять плагины VisualVM?

Если вы создаёте плагин VisualVM в NetBeans IDE, можно щёлкнуть проект правой кнопкой и выбрать «Create NBM». Вы получите файл NBM, который является ZIP-файлом, понятным VisualVM. Этот файл NBM можно установить в VisualVM через Plugin Manager (диспетчер плагинов). Файл NBM можно распространять по электронной почте или разместив его на сервере и сообщив пользователям, откуда его взять. Можно также создать так называемый «update center» (центр обновлений) — XML-файл, определяющий расположение и описание файла NBM, который пользователи регистрируют в своём Plugin Manager и затем используют для доступа к вашим плагинам VisualVM.

Использование графиков VisualVM

Начиная с VisualVM 1.2 разработчикам доступен открытый API для создания графиков. См. документацию VisualVM Charts API. Цель библиотеки — помочь разработчикам плагинов VisualVM визуализировать живые данные с минимальными усилиями, используя стандартизированный пользовательский интерфейс.

Библиотека не предназначена для универсальных, полнофункциональных и настраиваемых графиков. Она ориентирована на простое использование и низкую нагрузку на CPU и память даже при высокой нагрузке. Графики можно использовать в любых приложениях NetBeans Platform или Swing, но основная и единственная поддерживаемая платформа — VisualVM.

Возможности

Типы графиков

Текущая версия библиотеки VisualVM Charts реализует один тип графика — простой XY-график. Это наиболее часто используемый график для отображения живых данных. График очень легко настроить и использовать, поскольку почти все его возможности предопределены и фиксированы.

Составные части

Простой XY-график состоит из следующих частей:

  • Настраиваемый заголовок графика. Внешний вид заголовка можно настроить с помощью HTML-строки.
  • Настраиваемые описания осей графика. Внешний вид описаний можно настроить с помощью HTML-строк.
  • Настраиваемая область сведений, отображающая дополнительные текстовые данные. Если она задана, область сведений отображается только при достаточном месте для графика. В противном случае она автоматически сворачивается.
  • Тело графика, графически отображающее значения элементов. Помимо настройки внешнего вида элементов тело графика никак настроить нельзя. При наведении отображается интерактивная подсказка со значениями элементов в текущей позиции указателя. Подсказка показывается автоматически и её нельзя настроить или отключить.
  • Легенда графика, показывающая имена и цвета элементов. У элементов можно дополнительно отображать флажки, чтобы пользователь мог показывать или скрывать значения элементов в теле графика.

Элементы и значения графика

Простой XY-график поддерживает отображение неограниченного числа элементов. Однако рекомендуемый максимум для разумного удобства использования — 4 элемента на график. Элементы можно отрисовывать комбинацией обводки и заливки с настраиваемыми цветами и толщиной обводки. Если не задано, графики используют предопределённые цвета и градиенты. Это рекомендуемый подход, обеспечивающий визуальную согласованность всех графиков VisualVM.

Элементы на одном графике используют одни и те же единицы измерения и должны иметь сходные диапазоны значений. Это значит, что один график не может одновременно отображать относительные (%) и байтовые (B/MB) элементы и не должен отображать два десятичных элемента с разными диапазонами значений (0~10 против 50~50.000). Элементы и значения можно дополнительно описать в области сведений графика, предоставляя дополнительные метрики, такие как агрегированные значения, средние значения и т. д.

Буфер данных простого XY-графика поддерживает только значения long. Для графика можно задать постоянный коэффициент double, чтобы отображать данные как десятичные числа. Буфер данных создаётся с фиксированной ёмкостью и работает по принципу FIFO — самые старые значения отбрасываются при добавлении новых. При добавлении новых данных в буфер метка времени значений должна возрастать — каждый следующий пакет данных должен добавляться с большей меткой времени, чем предыдущий.

Отображение данных

Способ отображения значений простым XY-графиком фиксирован и не может быть изменён. График всегда отображает все значения, хранящиеся в его буфере данных. Пока число значений меньше ёмкости буфера, график работает в режиме «по ширине». Когда буфер данных заполнен, график начинает «прокручиваться» (самые старые значения отбрасываются при добавлении новых). Простой XY-график не предоставляет интерактивного масштабирования или прокрутки.

При отображении элементов график автоматически обновляет вертикальную шкалу, чтобы показать все значения. Минимум и максимум обновляются автоматически во время работы, но их можно задать заранее при добавлении новых элементов. Это, например, полезно при отображении относительных значений, которые чаще всего меньше 50%, но график должен быть масштабирован по вертикали так, чтобы максимумом было 100%. График также поддерживает задание начальной вертикальной шкалы до сбора каких-либо данных.

Сохранение данных

Базовый буфер данных графика поддерживает сохранение, предоставляя базовые операции загрузки и сохранения. Значения сохраняются в собственном двоичном формате, не предназначенном для повторного использования или изменения другими приложениями. Данные можно загрузить из постоянного хранилища до отображения графика. Поскольку буфер данных графика требует, чтобы значения добавлялись только с возрастающими метками времени, не рекомендуется загружать сохранённые данные после добавления любых живых значений на график. Операции загрузки и сохранения всегда следует вызывать в рабочем потоке.

Производительность графика

Графики рассчитаны на минимально возможные накладные расходы по производительности и памяти. Производительность отрисовки можно описать как O(min(values count, chart width [px])). Использование памяти можно описать как O(min(values count, buffer size)).

Внешний вид графика графически богат при локальном отображении, но загрузка CPU при отрисовке остаётся низкой благодаря аппаратно ускоренным внеэкранным буферам. Для удалённых сеансов X качество отрисовки автоматически снижается: не используются градиенты и прозрачность, отключается сглаживание. Это обеспечивает хорошие время перерисовки и отзывчивость для удалённых экземпляров графиков.

Описание API

VisualVM Charts API определён в документации VisualVM Charts API. Текущая версия предоставляет следующие классы:

  • ChartFactory: класс для создания объектов графиков на основе предоставленных дескрипторов. Сейчас доступен один тип графика — простой XY-график.
  • SimpleXYChartDescriptor: класс для описания внешнего вида и определения элементов создаваемого графика. Обратите внимание, что эти параметры можно задать только до создания графика. После создания внешний вид и элементы графика фиксированы.
  • SimpleXYChartSupport: дескриптор для доступа к графику и управления им во время работы. Позволяет добавлять новые значения на график, обновлять текстовую область сведений графика и предоставляет экземпляр JComponent, представляющий график. Также позволяет красиво форматировать значения графика и предоставляет базовые операции сохранения для сохранения и загрузки значений графика.

Простой XY-график реализует три типа графиков:

  • SimpleXYChartDescriptor.decimal(...): график, отображающий десятичные значения без единиц измерения. Этот график используется для отображения Classes (Классы) и Threads (Потоки) на вкладке Monitor в VisualVM.
  • SimpleXYChartDescriptor.bytes(...): график, отображающий значения памяти с единицами B/MB. Этот график используется для отображения Heap (Куча) и PermGen на вкладке Monitor в VisualVM.
  • SimpleXYChartDescriptor.percent(...): график, отображающий относительные (процентные) значения с единицами %. Этот график используется для отображения использования CPU и активности GC на вкладке Monitor в VisualVM.

Методы SimpleXYChartDescriptor для создания дескрипторов графиков decimal, bytes и percent используют (некоторые из) следующих параметров:

  • minValue: минимальное значение графика (управляет внешним видом при отображении данных, автоматически обновляется для новых значений).
  • maxValue: максимальное значение графика (управляет внешним видом при отображении данных, автоматически обновляется для новых значений).
  • initialYMargin: виртуальное первое значение графика (управляет начальным внешним видом до появления данных)
  • chartFactor: коэффициент для отображения значений графика (позволяет показывать десятичные числа: value = 33, chartFactor = 0.01, отображается 0.33)
  • hideableItems: определяет, сможет ли пользователь скрывать элементы графика во время работы
  • valuesBuffer: задаёт размер буфера данных графика (управляет числом отображаемых элементов)

Элементы графика можно определить в SimpleXYChartDescriptor с помощью простых методов add[Line|Fill|LineFill]Items(String... itemNames). Эти методы обеспечивают максимальную согласованность внешнего вида графика с другими графиками VisualVM за счёт предопределённых цветов и толщины линий по умолчанию. Пользовательский внешний вид элементов графика можно задать методом addItem(...) со следующими параметрами:

  • itemName: имя элемента, появляется в подсказке и легенде
  • itemColor: цвет, представляющий элемент (обычно lineColor или fillColor1), появляется в легенде
  • lineWidth: толщина обводки элемента, по умолчанию 2f
  • lineColor: цвет обводки элемента, значение null означает элемент-заливку
  • fillColor1: первый (верхний) цвет линейного градиента для заливки области элемента, значение null означает элемент-линию
  • fillColor2: второй (нижний) цвет линейного градиента для заливки области элемента, значение null означает отсутствие градиента (сплошная заливка)

Внешний вид графика можно дополнительно настроить методами SimpleXYChartDescriptor:

  • setChartTitle(String chartTitle): необязательно (по умолчанию нет), задаёт подпись графика. Заголовок графика поддерживает HTML-форматирование, например <html><big>Chart Title</big></html>.
  • set*AxisDescription(String *AxisDescription): необязательно (по умолчанию нет), задаёт описание осей графика. Описания осей поддерживают HTML-форматирование, например <html><i>Axis Descriptor</i></html>.
  • setDetailsItems(String[] detailNames): необязательно (по умолчанию нет), задаёт текстовую область над графиком. В этой области можно отображать любую информацию, периодически обновляемую SimpleXYChartSupport.updateDetails(String[] values), но обычно она показывает текущие и дополнительные (более подробные) значения элементов графика.


## Порядок разворачивания (после apply четырёх голых VPS)

1. **SSH-доступ и базовая настройка ОС** на всех 4 VPS — обновление пакетов, firewall, непривилегированный пользователь.
2. **VPS-1 (control plane) + VPS-2 (apps): установка Kubernetes** — например через `kubeadm` (control plane на VPS-1, join VPS-2 как worker через изолированную сеть `reactive_net`).
3. **VPS-3: установка PostgreSQL** напрямую (apt/Docker) — без managed-БД, так как Serverspace её не предоставляет как API-ресурс.
4. **VPS-4: установка GitLab Omnibus** — по инструкции из раздела 12–15 вашего гайда (DNS, Let's Encrypt, Runner).
5. **Связка компонентов**: приложения на VPS-2 обращаются к PostgreSQL на VPS-3 по приватной сети; GitLab CI/CD на VPS-4 деплоит в K8s на VPS-1/2.
6. **Переписать раздел 10** документа — заменить `registry_server.tf/kubernetes.tf/database.tf/s3.tf` на реальную схему: один `main.tf` с 4 VPS + отдельный этап "ручная настройка по SSH" для K8s/Postgres/GitLab.

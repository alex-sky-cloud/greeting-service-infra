# Памятка: где и как добавить правила в Cursor

Чтобы не повторять одно и то же в каждом чате, задайте правила **один раз**. Cursor подставляет их в Agent автоматически.

<a id="map"></a>

## Карта: что где лежит

| Тип | Где создавать | Файл / экран | На все проекты? | В git? |
|-----|----------------|--------------|-----------------|--------|
| **User Rules** | Настройки Cursor | Settings → Rules → **User Rules** | Да | Нет (только на вашем ПК) |
| **Project Rules** | Папка проекта | `.cursor/rules/*.mdc` | Нет (только этот репо) | Да |
| **AGENTS.md** | Корень проекта | `AGENTS.md` | Нет | Да |
| **Team Rules** | Веб-панель Cursor | cursor.com (Team/Enterprise) | Да, для команды | Через dashboard |

**Приоритет** (если правила пересекаются): Team → Project → User.

<a id="user-rules"></a>

## 1. User Rules — для всех проектов

**Где:** Cursor IDE → **Settings** → **Rules** → блок **User Rules**.

**Как открыть Settings:**
- `Ctrl + ,` (Windows/Linux) или `Cmd + ,` (macOS)
- или меню **File → Preferences → Cursor Settings**
- в чате: шестерёнка → **Cursor Settings**

**Как создать / изменить:**
1. Откройте **Cursor Settings**.
2. Слева или в поиске найдите **Rules** (иногда **Rules, Commands**).
3. Прокрутите до **User Rules**.
4. В большое текстовое поле вставьте правила (обычный markdown или список).
5. Закройте настройки — **сохраняется автоматически**.

**Формат:** простой текст, **без** YAML frontmatter и **без** `.mdc`.

**Пример содержимого (не привязан к проекту):**
```
- Отвечай на русском.
- Коротко, порциями: один шаг — жду результат — следующий шаг.
- Терминал: WSL Ubuntu, не PowerShell.
```

**Когда использовать:** язык, тон, кто запускает команды, личные привычки.

<a id="project-rules"></a>

## 2. Project Rules — для одного репозитория

**Где на диске:**

```
ваш-проект/
  .cursor/
    rules/
      my-rule.mdc
      terraform.mdc
```

Для этого репо:

```
D:\!_Проекты инфраструктуры\greeting-service-infra\.cursor\rules\
```

<a id="project-rules-ui"></a>

### Способ А — через интерфейс Cursor (рекомендуется)

1. **Cursor Settings** → **Rules, Commands**.
2. Раздел **Project Rules** — список правил текущего проекта.
3. Кнопка **+ Add Rule** (или **New Cursor Rule**).
4. Cursor создаст файл в `.cursor/rules/` и откроет его в редакторе.
5. Заполните frontmatter и текст → сохраните (`Ctrl + S`).

В том же экране видно: включено ли правило, тип активации (Always / Auto / Globs / Manual).

<a id="project-rules-manual"></a>

### Способ Б — вручную в проводнике / IDE

1. Создайте папку `.cursor/rules/` в **корне репозитория** (рядом с `app/`, `infra/`).
2. Создайте файл `имя-правила.mdc` (обязательно расширение **`.mdc`**).
3. Вставьте шаблон ниже → сохраните.

<a id="project-rules-chat"></a>

### Способ В — из чата Agent

1. В Agent-чате введите **`/create-rule`**.
2. Опишите, что должно быть в правиле.
3. Agent создаст файл в `.cursor/rules/` с frontmatter.

<a id="project-rules-format"></a>

### Формат файла `.mdc`

```markdown
---
description: Кратко — когда это правило нужно (для Agent)
globs: infra/terraform/**/*
alwaysApply: false
---

# Заголовок

Текст правил для AI...
```

**Поля frontmatter:**

| Поле | Назначение |
|------|------------|
| `alwaysApply: true` | Правило **всегда** в каждом чате этого проекта |
| `alwaysApply: false` + `globs: ...` | Только когда открыты/упомянуты файлы по маске |
| `alwaysApply: false` + `description: ...` | Agent сам решает, релевантно ли (Intelligent) |
| Без globs и без alwaysApply | Только если в чате написать **`@имя-файла`** |

**Маски `globs` (примеры):**
- `infra/terraform/**/*.tf` — все `.tf` в terraform
- `**/*.md` — все markdown в проекте

**В git:** закоммитьте `.cursor/rules/` — правила получит команда.

<a id="agents-md"></a>

## 3. AGENTS.md — простая альтернатива

**Где:** файл **`AGENTS.md`** в корне проекта (или в подпапке — действует на неё и ниже).

**Как создать:**
1. В корне репо: **New File** → `AGENTS.md`.
2. Обычный markdown, **без** frontmatter.
3. Сохранить.

**Когда использовать:** простые инструкции, совместимость с другими AI-инструментами. Меньше контроля, чем у `.mdc`.

## 4. Что куда писать (логика, не содержание)

| Тема | User Rules | Project Rules `.mdc` |
|------|------------|----------------------|
| «Отвечай на русском» | ✓ | |
| «Работай через WSL» | ✓ | |
| Preset_id, регион Terraform | | ✓ |
| Стиль комментариев в `.tf` | | ✓ (globs на `infra/terraform/**`) |

<a id="current-chat"></a>

## 5. Как подключить правила к **текущему** чату (пошагово)

Cursor **не перечитывает** правила в уже открытом чате после того, как вы их создали или изменили. Для **этого** чата есть два способа.

<a id="rule-names"></a>

### Откуда берётся «имя» правила

**Имя = имя файла** в `.cursor/rules/`, **без** расширения `.mdc`.

Пример для этого репозитория:

```
greeting-service-infra/.cursor/rules/communication-ru.mdc   →  @communication-ru
greeting-service-infra/.cursor/rules/terraform-timeweb.mdc  →  @terraform-timeweb
```

Имена **не придумываются** — смотрите в дереве файлов Cursor слева:

```
greeting-service-infra
  └── .cursor
        └── rules
              ├── communication-ru.mdc
              └── terraform-timeweb.mdc
```

<a id="current-chat-at"></a>

### Способ 1 — остаться в этом чате (через `@`)

**Шаг 1.** Откройте **этот** чат Agent (поле ввода внизу).

**Шаг 2.** Кликните в поле ввода сообщения.

**Шаг 3.** Наберите символ **`@`**.

**Шаг 4.** Появится **выпадающий список**. Найдите пункт:
- `communication-ru`
- `terraform-timeweb`  
  или раздел **Rules** / **Project Rules** с этими именами.

**Шаг 5.** **Кликните** по нужному пункту мышкой.

**Шаг 6.** В поле появится `@communication-ru` (или другое имя) — это нормально.

**Шаг 7.** Допишите вопрос и отправьте сообщение.

Правило подключится к **этому** сообщению. В следующих сообщениях при необходимости снова укажите `@communication-ru`.

<a id="current-chat-troubleshoot"></a>

### Если после `@` нет списка или нет ваших правил

**Проверка 1 — файлы на месте?**

Должна быть папка:

```
D:\!_Проекты инфраструктуры\greeting-service-infra\.cursor\rules\
```

с файлами `.mdc`. Без неё правила в `@` **не появятся**.

**Проверка 2 — открыт корень проекта?**

Cursor должен быть открыт на папке **`greeting-service-infra`**, а не только на `infra/terraform`.

**Проверка 3 — ввести имя вручную**

Наберите в поле ввода целиком:

```text
@communication-ru
```

и отправьте сообщение.

<a id="current-chat-new"></a>

### Способ 2 — новый чат (без `@`, проще)

**Шаг 1.** `Ctrl+L` (или иконка чата).

**Шаг 2.** **New Chat** / **Новый чат**.

**Шаг 3.** Пишите как обычно — Project Rules подтянутся **сами** (если `alwaysApply: true` — всегда; иначе — по условиям в frontmatter).

`@` в новом чате **не обязателен**.

<a id="current-chat-user-rules"></a>

### User Rules (Settings) — отдельно

Текст в **Cursor Settings → Rules → User Rules** **не** вызывается через `@`.

Он работает в **новых** чатах автоматически. В **старом** чате — только **новый чат** или скопируйте нужное в сообщение вручную.

<a id="current-chat-summary"></a>

### Кратко

| Цель | Действие |
|------|----------|
| Узнать имя для `@` | Имя файла в `.cursor/rules/` без `.mdc` |
| Правило в **этом** чате | `@` → выбрать правило → отправить |
| Правила **сами**, без `@` | **Новый чат** после сохранения правил |

<a id="verify"></a>

## 6. Как проверить, что правило работает

1. **Новый чат** Agent (или `@имя-правила` в текущем — см. [раздел 5](#current-chat)).
2. **Cursor Settings → Rules** — правило в списке Project Rules, статус включено.
3. Задайте вопрос по теме правила — ответ должен следовать ему без напоминания.

---

<a id="errors"></a>

## 7. Частые ошибки

| Проблема | Причина |
|----------|---------|
| Правило не работает | Файл не `.mdc` или нет frontmatter `---` |
| Правило не работает | Правили в старом `.cursorrules`, а Agent смотрит `.cursor/rules/` |
| User Rules не видны | Искали Project Rules; User — только в Settings |
| Не сработало сразу | Нужен **новый** чат после сохранения |

---

<a id="legacy"></a>

## 8. Устаревшее (не использовать для новых правил)

| Файл | Статус |
|------|--------|
| `.cursorrules` в корне | Legacy, постепенно выводится |
| `.md` в `.cursor/rules/` без frontmatter | **Игнорируется** — нужен `.mdc` или AGENTS.md |

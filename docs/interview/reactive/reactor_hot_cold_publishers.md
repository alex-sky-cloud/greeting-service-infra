## 1. Разница между Cold и Hot

- **Cold Publisher** — каждый новый подписчик получает данные "с нуля", независимо от других подписчиков. Аналог подкаста: каждый слушатель начинает с начала.
- **Hot Publisher** — данные эмитятся независимо от подписки; подключившиеся позже подписчики видят только то, что происходит ПОСЛЕ их подписки. Аналог живого радио-эфира: подключился позже — пропустил начало.

По умолчанию **все Publisher в Reactor — cold**:

```java
Flux<Long> cold = Flux.interval(Duration.ofSeconds(1));
cold.subscribe(a -> log.info("A: {}", a)); // считает с 0
Thread.sleep(3000);
cold.subscribe(b -> log.info("B: {}", b)); // ТОЖЕ считает с 0, независимо от A
```

## 2. cache() — снапшот, а не живой эфир

`cache()` делает cold-поток одноразовым: первый подписчик реально выполняет запрос, результат сохраняется, все последующие подписчики получают тот же результат — даже если подключились намного позже. Это НЕ hot-поведение в смысле "живого эфира", а скорее "прочитали одну и ту же уже готовую газету".

```java
Mono<UserProfile> profile = userService.fetchProfile(id).cache();
profile.subscribe(a -> log.info("A: {}", a)); // реальный запрос выполняется
profile.subscribe(b -> log.info("B: {}", b)); // получает тот же результат из кэша, без нового запроса
```

Применение: данные, которые не меняются в рамках жизни объекта/запроса (справочники, конфигурация, разово посчитанный агрегат).

## 3. Иерархия hot-операторов

### Базовый уровень — publish()

Превращает cold `Flux` в `ConnectableFlux` — подготовленный к hot-режиму объект. Сам по себе ничего не эмитит, пока не вызван `connect()`.

```java
ConnectableFlux<Long> connectable = Flux.interval(Duration.ofSeconds(1)).publish();
```

### Способ запуска 1 — вручную через connect()

```java
connectable.subscribe(a -> log.info("A: {}", a)); // просто регистрируется
connectable.subscribe(b -> log.info("B: {}", b)); // просто регистрируется
connectable.connect(); // ТОЛЬКО теперь начинается эмиссия для всех подписчиков сразу
```

### Способ запуска 2 — autoConnect(n)

Запускает эмиссию автоматически, когда наберётся n подписчиков. НЕ отключается, даже если все подписчики отвалятся.

```java
Flux<Long> hot = Flux.interval(Duration.ofSeconds(1))
    .publish()
    .autoConnect(2); // старт сам, когда подключится 2-й подписчик
```

### Способ запуска 3 — refCount(n)

То же самое, что `autoConnect(n)`, но с дополнительным поведением: считает активных подписчиков и при падении их числа до нуля отключает upstream (`dispose()`), а при появлении новых — переподключается заново (рестарт).

```java
Flux<Long> hot = Flux.interval(Duration.ofSeconds(1))
    .publish()
    .refCount(2); // старт при 2 подписчиках, СТОП при 0, возможен рестарт
```

## 4. share() — шорткат для refCount(1)

`share()` эквивалентен `publish().refCount(1)` для `Flux` (аналогично для `Mono`). Это самый частый способ получить "живой эфир" с минимальным порогом в одного подписчика.

```java
Flux<Long> ticker = Flux.interval(Duration.ofSeconds(1)).share();
ticker.subscribe(t -> log.info("A sees: {}", t));
// через 3 секунды подключается B
ticker.subscribe(t -> log.info("B sees: {}", t)); // B пропустил первые 3 события
```

---

## 5. Итоговая схема

```
Flux.publish()                    -> ConnectableFlux (управление вручную)
    |-- .connect()                -> запуск в конкретный момент, независимо от числа подписчиков
    |-- .autoConnect(n)           -> запуск сам при n подписчиках; НЕ останавливается
    |-- .refCount(n)              -> запуск при n подписчиках + автостоп при 0 + рестарт
    `-- .share() == refCount(1)   -> шорткат для самого частого случая

cache()                           -> НЕ hot-поведение; одноразовый снапшот для всех подписчиков
```

## 6. Сравнительная таблица

| Оператор | Запуск эмиссии | Остановка при 0 подписчиков | Повторный запуск | Типичный кейс |
|---|---|---|---|---|
| `cache()` | При первой подписке | Нет (данные хранятся вечно/по TTL) | Нет | Справочники, разовый агрегат |
| `publish()` + `connect()` | Вручную, по команде разработчика | Нет | Только новый `connect()` | Точный контроль момента старта |
| `publish().autoConnect(n)` | Автоматически при n подписчиках | Нет | Нет | Разогрев потока для группы потребителей |
| `publish().refCount(n)` / `share()` | Автоматически при n подписчиках | Да | Да, при новой подписке | "Живой эфир" с экономией ресурсов между волнами подписчиков |

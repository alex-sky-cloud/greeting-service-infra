## Короткий ответ

**Утверждение:**
Да, `Mono.flatMap(...)` тоже работает через внутренний `Publisher`, и официальная документация это подтверждает. Но из-за того, что `Mono` по определению испускает не больше одного элемента, `Mono.flatMap(...)` внешне часто выглядит почти как `map(...)`. При этом по смыслу это всё равно не `map`: `map` возвращает обычное значение, а `flatMap` возвращает другой `Mono`, то есть другой `Publisher`.

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html

EN:

> "A Reactive Streams Publisher with basic rx operators that emits at most one item via the onNext signal then terminates with an onComplete signal..."

RU:

> «Reactive Streams Publisher с базовыми rx-операторами, который испускает не более одного элемента через сигнал onNext, а затем завершается сигналом onComplete...»

EN:

> "For instance flatMap returns a Mono, while there is a flatMapMany alias with possibly more than 1 emission."

RU:

> «Например, `flatMap` возвращает `Mono`, тогда как существует alias `flatMapMany` для случая, где возможна более чем одна эмиссия.»

## Что такое Mono с точки зрения спецификации

**Утверждение:**
`Mono` — это не просто “одно значение”, а полноценный `Publisher`. Это важно, потому что если mapper внутри `flatMap` возвращает `Mono`, то он возвращает именно `Publisher`, а не обычный объект.

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html

EN:

> "All Implemented Interfaces: Publisher, CorePublisher"

RU:

> «Реализуемые интерфейсы: `Publisher`, `CorePublisher`.»

**Источник:**
https://www.reactive-streams.org/reactive-streams-1.0.2-javadoc/org/reactivestreams/Publisher.html

EN:

> "A Publisher is a provider of a potentially unbounded number of sequenced elements, publishing them according to the demand received from its Subscriber(s)."

RU:

> «`Publisher` — это поставщик потенциально неограниченного числа упорядоченных элементов, публикующий их в соответствии со спросом, полученным от своих `Subscriber`-ов.»

**Пояснение:**
Из этого следует простая вещь: даже если конкретный `Publisher` испускает максимум один элемент, он всё равно остаётся `Publisher`. Поэтому `Mono`, возвращённый из `flatMap`, — это и есть внутренний publisher.

***

## Что официально говорит документация про Mono.flatMap

**Утверждение:**
Официальная документация Reactor прямо различает `flatMap` и `flatMapMany` у `Mono`. Это ключевое подтверждение: `Mono.flatMap(...)` работает как переход к другому publisher-источнику, но результат сохраняет семантику “0..1”. Если бы это был просто `map`, такой отдельной модели и отдельного alias `flatMapMany` не понадобилось бы.

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html

EN:

> "The rx operators will offer aliases for input Mono type to preserve the \"at most one\" property of the resulting Mono. For instance flatMap returns a Mono, while there is a flatMapMany alias with possibly more than 1 emission."

RU:

> «Rx-операторы предоставляют alias для входного типа `Mono`, чтобы сохранить свойство результирующего `Mono` — “не более одного”. Например, `flatMap` возвращает `Mono`, тогда как `flatMapMany` — alias для случая, где возможно более одной эмиссии.»

**Утверждение:**
Это означает: `Mono.flatMap(...)` не просто преобразует значение `T` в `R`, а преобразует значение `T` в другой publisher типа `Mono<R>`, после чего цепочка продолжается уже через него.

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html\#flatMap(java.util.function.Function)

EN:

> "Transform the item emitted by this Mono asynchronously, returning the value emitted by another Mono."

RU:

> «Асинхронно преобразует элемент, испущенный этим `Mono`, возвращая значение, испущенное другим `Mono`.»

## Почему Mono.flatMap визуально похож на map

**Утверждение:**
Твоё ощущение, что `Mono.flatMap(...)` похож на `map(...)`, не ошибочно на уровне “внешнего поведения”. Причина в том, что у исходного `Mono` максимум один элемент, и у внутреннего `Mono` после `flatMap` тоже обычно максимум один элемент. Поэтому внешне цепочка выглядит как простое преобразование одного значения в другое.

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html

EN:

> "A Reactive Streams Publisher with basic rx operators that emits at most one item..."

RU:

> «Reactive Streams Publisher с базовыми rx-операторами, который испускает не более одного элемента...»

**Утверждение:**
Но по механике это разные операции. `map` делает преобразование “значение -> значение”, а `flatMap` делает преобразование “значение -> другой Mono”, после чего Reactor подписывается уже на этот другой `Mono`.

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html\#flatMap(java.util.function.Function)

EN:

> "Transform the item emitted by this Mono asynchronously, returning the value emitted by another Mono."

RU:

> «Асинхронно преобразует элемент, испущенный этим `Mono`, возвращая значение, испущенное другим `Mono`.»

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html\#map(java.util.function.Function)

EN:

> "Transform the item emitted by this Mono by applying a synchronous function to it."

RU:

> «Преобразует элемент, испущенный этим `Mono`, применяя к нему синхронную функцию.»

***

## Точная формула различия

**Утверждение:**
Правильная формула такая:

- `map`: `T -> R`
- `Mono.flatMap`: `T -> Mono<R>`
- `Flux.flatMap`: `T -> Publisher<R>` для многих элементов с последующим flatten/merge

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html\#map(java.util.function.Function)

EN:

> "Transform the item emitted by this Mono by applying a synchronous function to it."

RU:

> «Преобразует элемент, испущенный этим `Mono`, применяя к нему синхронную функцию.»

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html\#flatMap(java.util.function.Function)

EN:

> "Transform the item emitted by this Mono asynchronously, returning the value emitted by another Mono."

RU:

> «Асинхронно преобразует элемент, испущенный этим `Mono`, возвращая значение, испущенное другим `Mono`.»

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Flux.html\#flatMap(java.util.function.Function)

EN:

> "Transform the elements emitted by this Flux asynchronously into Publishers, then flatten these inner publishers into a single Flux through merging, which allow them to interleave."

RU:

> «Асинхронно преобразует элементы, испущенные этим `Flux`, в `Publisher`-ы, затем расплющивает эти внутренние publisher-ы в единый `Flux` через merge, что позволяет их элементам перемешиваться.»

**Итоговая формулировка:**
Значит, правда такая: `Mono.flatMap(...)` действительно создаёт переход к **внутреннему publisher**, просто этим publisher обычно является другой `Mono`, а не многозначный `Flux`. Поэтому визуально он может быть похож на `map`, но по типу и по семантике это именно `flatMap`, а не `map`.

## Мини-пример

**Утверждение:**
Вот на уровне типов разница выглядит так:

```java
Mono<UserDto> a = userMono.map(user -> toDto(user));
Mono<UserDto> b = userMono.flatMap(user -> userService.loadDto(user.id()));
```

В первом случае `toDto(user)` возвращает обычный `UserDto`, поэтому нужен `map`. Во втором случае `loadDto(...)` возвращает `Mono<UserDto>`, поэтому нужен `flatMap`.

**Источник:**
https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html\#flatMap(java.util.function.Function)

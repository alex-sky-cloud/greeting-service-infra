## 1. Общий контекст

Оба оператора применяются, когда подписчик временно не готов принимать элементы (`demand = 0`), и оба не используют полноценный буфер для накопления истории. Различие проявляется в конкретный момент — когда подписчик открывает demand и сигнализирует `request(n)`.

## 2. onBackpressureDrop

Пока `demand = 0`, все входящие элементы безвозвратно отбрасываются — ничего не сохраняется. Когда подписчик открывает demand, он получает только тот элемент, который источник эмитирует **после** этого момента. Если в момент открытия demand источник ничего не эмитит, подписчик просто ждёт следующего элемента с нуля, как будто предыдущих не было.

## 3. onBackpressureLatest

Пока `demand = 0`, оператор хранит ровно одну ячейку, куда постоянно перезаписывается самый свежий пришедший элемент (перетирая предыдущий). Как только подписчик открывает demand, оператор немедленно отдаёт значение из этой ячейки — даже если источник в этот момент не эмитил ничего нового.

## 4. Ключевое отличие

| Критерий | onBackpressureDrop | onBackpressureLatest |
|---|---|---|
| Хранение элементов при demand=0 | Не хранит ничего | Хранит последний элемент в одной ячейке |
| Что получает подписчик при открытии demand | Только новый элемент, пришедший после открытия | Немедленно последнее сохранённое значение |
| Задержка при получении данных | Может ждать до следующей эмиссии источника | Нет задержки — данные готовы сразу |
| Подходит для | Сценариев, где допустима пауза до следующего значения | Сценариев, где нужно всегда актуальное последнее значение |

## 5. Практический пример

Курс валют на бирже:

- С `onBackpressureDrop` подписчик может ждать секунды до следующего тика биржи, если demand открылся в "тихий" момент.
- С `onBackpressureLatest` подписчик сразу получает актуальную последнюю цену, не дожидаясь нового прихода данных от источника.

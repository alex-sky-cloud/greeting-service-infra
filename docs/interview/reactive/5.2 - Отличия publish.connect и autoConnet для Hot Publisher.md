## Введение

`publish()` сам по себе **не запускает source**. Он превращает `Flux` в `ConnectableFlux`: подписчики могут подключиться и ждать, но upstream начнёт генерировать данные только после `connect()` или автоматически через `autoConnect(...)` / `refCount(...)`.[^1]

## Базовая идея

```java
Flux<Metric> source = ...;          // обычно cold source
ConnectableFlux<Metric> hot = source.publish();
```

После `publish()`:

- `hot.subscribe(...)` подключает подписчика **к `hot`**;
- но `source` ещё не получает `subscribe()`;
- следовательно, source пока ничего не генерирует.

`publish()` нужен, чтобы несколько подписчиков затем делили **одну** upstream-подписку, а не создавали отдельную подписку на source для каждого из них.[^1]

## `connect()` — запуск вручную

```java
ConnectableFlux<Metric> hot = source.publish();

hot.subscribe(metric -> System.out.println("A: " + metric));
hot.subscribe(metric -> System.out.println("B: " + metric));

Disposable connection = hot.connect(); // source подписывается и начинает работу
```

До `connect()` A и B ждут. После `connect()`:

```text
source → publish → A
                 → B
```

`connect()` возвращает `Disposable`: вызов `connection.dispose()` разрывает соединение с upstream.[^2]

Используйте `connect()`, когда **вы сами определяете точный момент старта**: например, сначала регистрируете всех нужных consumers, затем запускаете источник.

## `autoConnect(n)` — запуск при N подписчиках

```java
Flux<Metric> hot = source.publish().autoConnect(2);
```

Здесь всё происходит автоматически:

1. Первый подписчик вызывает `subscribe()` → ждёт.
2. Второй подписчик вызывает `subscribe()` → threshold `2` достигнут.
3. Reactor сам делает внутренний `connect()`.
4. Source запускается, и оба подписчика получают новые данные.
```text
A subscribes → ожидание
B subscribes → source стартует
              → A получает новые Metric
              → B получает новые Metric
```

**Ключевой момент:** 

 - `autoConnect(2)` **не отключает source**, когда A и B отменят подписки. 
 - После достижения порога соединение остаётся активным до terminal signal source (`complete`/`error`) либо до ручного отключения, если вы использовали overload с `Consumer<Disposable>`.

Например:

```java
Flux<Metric> hot = source.publish().autoConnect(1);
```

**

 - «при первом подписчике начать source и дальше не отключать его автоматически». 
 - Это близко по стартовому поведению к `share()`, но жизненный цикл при отсутствии подписчиков отличается.

## Как остановить `connect()`

```java
Flux<Long> source = Flux.interval(Duration.ofSeconds(1));

ConnectableFlux<Long> published = source.publish();

Disposable subscriber = published.subscribe(
    value -> System.out.println("metric: " + value)
);

Disposable connection = published.connect();

// ... source работает и производит значения

subscriber.dispose(); // подписчик ушёл
                       // source всё ещё продолжает работать

connection.dispose(); // source отключён и прекращает работу
```

`subscriber.dispose()` отменяет подписку конкретного потребителя.

`connection.dispose()` отключает `published` от upstream source. Именно поэтому для `connect()` нужно сохранить результат `connect()` в переменную.

- Источник: https://projectreactor.io/docs/core/release/api/reactor/core/publisher/ConnectableFlux.html

EN:

> “the `Disposable` that allows disconnecting the connection after.”

RU:

> «`Disposable`, который позволяет позднее отключить соединение».

## Как остановить `autoConnect(2)`

Вариант без callback:

```java
Flux<Long> hot = source.publish().autoConnect(2);
```

не даёт вам `Disposable` подключения. Поэтому остановить source через него вручную нельзя.

Нужно использовать overload с callback:

```java
AtomicReference<Disposable> connectionRef = new AtomicReference<>();

Flux<Long> hot = source.publish()
    .autoConnect(2, connectionRef::set);
```

Полный пример:

```java
AtomicReference<Disposable> connectionRef = new AtomicReference<>();

Flux<Long> hot = Flux.interval(Duration.ofSeconds(1))
    .publish()
    .autoConnect(2, connectionRef::set);

Disposable firstSubscriber = hot.subscribe(
    value -> System.out.println("A: " + value)
);

// Source ещё не запущен: подписчик пока только один.

Disposable secondSubscriber = hot.subscribe(
    value -> System.out.println("B: " + value)
);

// Теперь подписчиков два.
// Reactor автоматически подключил source.
// connectionRef содержит Disposable этого подключения.

firstSubscriber.dispose();
secondSubscriber.dispose();

// Оба подписчика ушли,
// но source продолжает работать.

Disposable connection = connectionRef.get();

if (connection != null) {
    connection.dispose();
}

// Теперь source отключён.
```

В `autoConnect(2, connectionRef::set)` callback вызывается после автоматического подключения. Reactor передаёт в него `Disposable`, которым можно отключить source.

- Источник: https://projectreactor.io/docs/core/release/api/reactor/core/publisher/ConnectableFlux.html

EN:

> “Connects this `ConnectableFlux` to the upstream source when the specified amount of `Subscriber` subscribes and calls the supplied consumer with a `Disposable` that allows disconnecting.”

RU:

> «Подключает этот `ConnectableFlux` к upstream-источнику, когда подписывается указанное количество `Subscriber`, и вызывает переданный consumer с `Disposable`, позволяющим выполнить отключение».

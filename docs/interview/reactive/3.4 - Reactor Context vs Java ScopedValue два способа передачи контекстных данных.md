## 1. Что такое ScopedValue

`ScopedValue` — механизм в Java, задуманный как безопасная замена `ThreadLocal` специально для структурированной конкурентности и виртуальных потоков (Virtual Threads, Project Loom). Он позволяет привязать неизменяемое значение к текущему потоку выполнения на время работы конкретного блока кода через `ScopedValue.where(...).run(...)`.

Источник: https://www.happycoders.eu/java/scoped-values/

Java 21: JEP 446: Scoped Values (Preview)

Java 23: JEP 481: Scoped Values (Third Preview)
Java 24: JEP 487: Scoped Values (Fourth Preview)
Java 25: JEP 506: Scoped Values
Since Java 25, Scoped Values are final – you don't need to do anything else

Java 24: JEP 487: Scoped Values (Fourth Preview)

**Исправление:** в исходном тексте указывалось "preview начиная с Java 20-21" — это неточно. В Java 20 `ScopedValue` был incubator-фичей (JEP 429), а не preview, и прошёл ещё четыре раунда preview (Java 21-24), прежде чем был окончательно финализирован в Java 25 (JEP 506). На момент актуальности документа (Java 25 уже вышла) `ScopedValue` — это финальный, production-ready API, доступный без флагов `--enable-preview`.

Ключевой нюанс про наследование дочерними потоками, который требует уточнения:

Источник: https://docs.oracle.com/en/java/javase/22/docs/api/java.base/java/lang/ScopedValue.html

**EN:**
```
ScopedValue supports sharing across threads. This sharing is limited to
structured cases where child threads are started and terminate within the
bounded period of execution by a parent thread. When using a
StructuredTaskScope, scoped value bindings are captured when creating a
StructuredTaskScope and inherited by all threads started in that task scope
with the fork method.
```

**RU:**
```
ScopedValue поддерживает распространение между потоками. Это ограничено
структурированными случаями, когда дочерние потоки запускаются и
завершаются в рамках ограниченного периода выполнения родительского
потока. При использовании StructuredTaskScope привязки scoped value
захватываются при создании StructuredTaskScope и наследуются всеми
потоками, запущенными в этой области видимости через метод fork.
```

**Важное уточнение:** наследование значения дочерними потоками — не универсальное автоматическое свойство любого виртуального потока, а работает **только** через `StructuredTaskScope.fork()`. Обычный виртуальный поток, созданный вне `StructuredTaskScope` (например, через `Thread.startVirtualThread()` или `ExecutorService`), значение `ScopedValue` родителя не увидит.

Источник: https://devjava.substack.com/p/goodbye-threadlocal-understanding

**EN:**
```
This demonstrates that ScopedValue is NOT inherited by virtual threads
unless in a StructuredTaskScope.
```

**RU:**
```
Это демонстрирует, что ScopedValue НЕ наследуется виртуальными потоками,
если они не находятся внутри StructuredTaskScope.
```

## 2. Ключевое отличие от Reactor Context

- `ScopedValue` — решение на уровне потока (thread-based): работает, когда используется блокирующий, синхронный стиль кода на виртуальных потоках, где один логический запрос обрабатывается одним потоком (или структурированным деревом дочерних потоков через `StructuredTaskScope`) на всём протяжении.
- Reactor `Context` — решение на уровне подписки (subscription-based): не зависит от потока вообще, потому что в реактивной модели один логический запрос может исполняться на разных потоках по очереди через `subscribeOn`/`publishOn`.

## 3. Сравнительная таблица

| Критерий | Reactor Context | Java ScopedValue |
|---|---|---|
| Привязка | К цепочке подписки (Subscriber) | К текущему потоку выполнения |
| Совместимость с переключением потоков | Полная — переживает subscribeOn/publishOn | Не применим напрямую при произвольном переключении потоков |
| Целевая платформа | Реактивный стек (Project Reactor, WebFlux) | Виртуальные потоки (Project Loom), структурированная конкурентность, блокирующий стиль |
| Изменяемость | Неизменяемый (immutable), новый Context на каждую запись | Неизменяемое значение на время выполнения блока |
| Наследование дочерними задачами | Через явную передачу вдоль цепочки операторов | Автоматическое, но только внутри StructuredTaskScope.fork(); обычные потоки вне scope значение не наследуют |
| Статус в Java | — | Финализирован в Java 25 (JEP 506), до этого — incubator/preview в Java 20-24 |

## 4. Практический вывод

При переходе с реактивного стека (WebFlux + Reactor) на виртуальные потоки со структурированной конкурентностью `ScopedValue` становится аналогом `Context` — но эти два механизма несовместимы напрямую и работают по разным правилам наследования. Оба решают одну и ту же задачу — передачу контекстных данных без потери при асинхронности/конкурентности — но принципиально разными способами: один привязкой к структурированному дереву потоков через `StructuredTaskScope`, другой привязкой к цепочке подписки Reactor.

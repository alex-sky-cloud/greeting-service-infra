
# Вопрос и ответ: нужно ли вызывать `dispose()` после `connect()` и `autoConnect()`?

## Вопрос

Получается, что, например, я вызвал `connect()` и забыл вызвать на нём `dispose()`. 

Тогда **источник** _данных_ будет занимать сетевое соединение и генерировать данные, как и при `autoConnect()`: источник не отключается, даже если подписчики ушли?

То есть при `autoConnect()` мне тоже нужно вызвать `dispose()`?

## Ответ

Да. Если вызвать `connect()` и не вызвать `dispose()` у возвращённого `Disposable`, подключение к **source** останется **активным**. 
 - Даже **после отмены** всех **downstream**-подписок **source** продолжит работать: 
   - например, **удерживать сетевое соединение** либо генерировать элементы.

```java
ConnectableFlux<Metric> published = source.publish();

Disposable connection = published.connect();

// source подключён и работает

connection.dispose(); // отключает source
```

- Источник: https://projectreactor.io/docs/core/release/api/reactor/core/publisher/ConnectableFlux.html

EN:

> “Connect this `ConnectableFlux` to its source and return a `Disposable` that can be used for disconnecting.”

RU:

> «Подключает этот `ConnectableFlux` к его источнику и возвращает `Disposable`, который можно использовать для отключения».

## `connect()`

При `connect()` - `Disposable` возвращается непосредственно из вызова метода:

```java
Disposable connection = published.connect();
```

Именно этот объект **управляет** соединением между `published` и `source`.

```java
Disposable subscriber = published.subscribe(
    metric -> System.out.println(metric)
);

Disposable connection = published.connect();

subscriber.dispose(); // отменяет только данного подписчика

// source продолжает работать

connection.dispose(); // отключает published от source
```

То есть:

```text
subscriber.dispose()  → подписчик перестаёт получать данные.

connection.dispose()  → source отключается.
```

- Источник: https://projectreactor.io/docs/core/release/api/reactor/core/publisher/ConnectableFlux.html

EN:

> “the `Disposable` that allows disconnecting the connection after.”

RU:

> «`Disposable`, который позволяет позднее отключить соединение».

## `autoConnect(2)`

При таком варианте:

```java
Flux<Metric> hot = source.publish().autoConnect(2);
```

Reactor **подключит** source **автоматически**, когда появится второй подписчик.

Но `autoConnect(2)` возвращает `Flux<Metric>`, а не `Disposable` соединения. 
  - Поэтому в таком виде вручную остановить source через `dispose()` вы **не сможете**.

Чтобы сохранить `Disposable` подключения, нужно использовать **overload** с _callback_:

```java

AtomicReference<Disposable> connectionRef = new AtomicReference<>();

Flux<Metric> hot = source.publish()
    .autoConnect(2, connectionRef::set);
```

Когда подключится второй подписчик, Reactor выполнит подключение и передаст соответствующий `Disposable` в callback:

```java
connectionRef::set
```

Полный пример:

```java
AtomicReference<Disposable> connectionRef = new AtomicReference<>();

Flux<Long> hot = Flux.interval(Duration.ofSeconds(1))
    .publish()
    .autoConnect(2, connectionRef::set);

Disposable a = hot.subscribe(v -> System.out.println("A: " + v));
Disposable b = hot.subscribe(v -> System.out.println("B: " + v));

// После b.subscribe() source подключён и работает.

a.dispose();
b.dispose();

// Подписчики ушли, но source продолжает работать.

Disposable connection = connectionRef.get();

if (connection != null) {
    connection.dispose();
}

// Теперь source отключён.
```

**Итог**: 

 - да, при `autoConnect()` тоже нужно вызвать `dispose()` у `Disposable` подключения, если **source** необходимо остановить вручную. 
 - Но этот `Disposable` нужно получить заранее через `autoConnect(2, callback)`.

- Источник: https://projectreactor.io/docs/core/release/api/reactor/core/publisher/ConnectableFlux.html

EN:

> “Connects this `ConnectableFlux` to the upstream source when the specified amount of `Subscriber` subscribes and calls the supplied consumer with a `Disposable` that allows disconnecting.”

RU:

> «Подключает этот `ConnectableFlux` к upstream-источнику, когда подписывается указанное количество `Subscriber`, и вызывает переданный consumer с `Disposable`, позволяющим выполнить отключение».

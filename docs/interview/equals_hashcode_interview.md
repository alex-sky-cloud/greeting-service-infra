# equals() и hashCode(): контракт и типичные ошибки

## Контракт

Если два объекта равны по `equals()`, то их `hashCode()` обязательно должен возвращать одинаковое значение. Обратное не требуется: разные объекты могут иметь одинаковый `hashCode()`; такая ситуация называется коллизией.

Этот контракт важен для `HashMap`, `HashSet` и других hash-коллекций. При вставке или поиске коллекция сначала выбирает bucket по `hashCode()`, а уже внутри bucket сравнивает объекты через `equals()`.

## Почему важен hashCode()

Если `hashCode()` реализован неправильно, `equals()` может не вызваться: поиск попадёт в другой bucket. Поэтому корректный `hashCode()` необходим для корректной работы `HashMap` и `HashSet`.

## Типичные ошибки

- Переопределить `equals()`, но не переопределить `hashCode()`. Два логически равных объекта получат разные hash-коды, попадут в разные bucket, и `HashSet.contains()` или `HashMap.get()` не найдут нужный объект.
- Использовать изменяемое поле в `hashCode()`. Если объект уже находится в `HashSet` или является ключом `HashMap`, изменение такого поля меняет hash-код, но объект остаётся в прежнем bucket. После этого его трудно найти или удалить.
- Неправильно реализовать `equals()` и `hashCode()` в JPA entity. Не следует сравнивать объекты через точное совпадение `getClass()`, потому что Hibernate может подставить proxy-подкласс.
- Использовать генерируемый `id` в `hashCode()` без осторожности. Если `id` появляется только после сохранения entity, hash-код изменится, и объект может «потеряться» в уже созданной `HashSet`.

## JPA и Hibernate

Для JPA entity обычно используют бизнес-ключ либо идентификатор. Если бизнес-ключа нет, можно использовать `id`, но необходимо учитывать, что сгенерированный `id` становится доступен после сохранения.

Для value object удобнее использовать `record`: Java автоматически генерирует корректные `equals()` и `hashCode()` по его компонентам. В таком случае вручную реализовывать эти методы обычно не требуется.

## Короткий ответ на собеседовании

«Если два объекта равны по `equals()`, их `hashCode()` должен быть одинаковым. Обратное неверно: одинаковый `hashCode()` не гарантирует равенство, потому что возможны коллизии. `HashMap` и `HashSet` сначала выбирают bucket по `hashCode()`, а затем сравнивают объекты через `equals()`. Поэтому основные ошибки — переопределить `equals()` без `hashCode()`, использовать изменяемые поля в hash-коде и неправильно реализовать эти методы в JPA entity. Для value object удобно использовать `record`, который генерирует оба метода автоматически.»

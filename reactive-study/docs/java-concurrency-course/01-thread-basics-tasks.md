## Правила

- Каждая задача — отдельный класс с методом `main`, написанный с нуля.
- Используются только средства темы 01. Конструкции следующих тем не нужны ни в одной задаче.
- В блоке «Что сделать» по пунктам сказано, кто выполняет действие и кто печатает строку. Каким методом это сделать, в условии не сказано.
- «Занимает N мс» значит, что это действие длится указанное время. Как изобразить эту длительность в коде, решает тот, кто выполняет задачу.
- Числа миллисекунд в образце — пример. Подходит любое значение из диапазона, указанного в задаче.
- Решение считается верным, если результат совпадает с блоком «Что сделать» при каждом запуске.

## Задача 1. Остатки трёх складов

**Ситуация:** утром система собирает остатки с трёх складов. Опрос одного склада занимает 1000 мс. Если опрашивать склады по очереди, отчёт будет готов через 3000 мс. Нужен отчёт примерно через 1000 мс.

Остатки: Москва — 120, Казань — 80, Самара — 50.

**Что сделать:**

1. Одновременно запустить три опроса: у каждого склада свой поток, опрос занимает 1000 мс.
2. Поток Москвы сохраняет число 120, поток Казани — 80, поток Самары — 50. Потоки ничего не печатают.
3. Основная программа печатает весь отчёт одна, и только после того, как все три числа уже сохранены.
4. Строка «Итого» — сумма этих трёх чисел. Число 250 в код не вписывать.
5. Время работы программы — меньше 1500 мс. Порядок строк — как в образце при каждом запуске.

**Образец вывода** (число миллисекунд — любое меньше 1500):

```text
Москва: 120
Казань: 80
Самара: 50
Итого: 250
Время: 1034 мс
```

## Задача 2. Письмо после оформления заказа

**Ситуация:** покупатель оформляет заказ 42. Письмо ему уходит следом, отправка занимает 2000 мс. Сообщение об оформлении он должен увидеть сразу.

**Что сделать:**

1. Основная программа сразу печатает, что заказ 42 оформлен. Время этой строки от старта программы — не больше 100 мс. К этому моменту письмо ещё не отправлено.
2. Отправку письма выполняет другой поток. Название этого потока — `mailer`. Отправка занимает 2000 мс.
3. Строку «Письмо по заказу 42 отправлено, исполнитель: mailer» печатает поток `mailer`. Слово `mailer` в строке — название этого потока.
4. Время второй строки — от 2000 до 2200 мс.
5. Программа заканчивается только после второй строки.

```text
[4 мс] Заказ 42 оформлен
[2007 мс] Письмо по заказу 42 отправлено, исполнитель: mailer
```

## Задача 3. Отмена выгрузки отчёта

**Ситуация:** отчёт выгружается постранично, всего 10 страниц. Одна страница занимает 400 мс. Через 1000 мс после старта пользователь нажимает «Отмена».

**Что сделать:**

1. Выгрузку выполняет один поток. После каждой готовой страницы он печатает «Страница N выгружена».
2. Через 1000 мс после старта выгрузки основная программа просит этот поток закончить. Принудительно уничтожать поток нельзя: он сам прекращает выгрузку.
3. Поток выгрузки печатает, сколько страниц успел выгрузить. Это 2 страницы. Страниц 3–10 в выводе нет, строки «Выгрузка завершена полностью» нет.
4. Строку «Отмена подтверждена» печатает основная программа, и только после того, как поток выгрузки уже завершился.

```text
Страница 1 выгружена
Страница 2 выгружена
Выгрузка отменена, выгружено страниц: 2
Отмена подтверждена
```

Строки «Выгрузка завершена полностью» или страниц 3–10 в выводе быть не должно.

## Задача 4. Остановка поиска без пауз

**Ситуация:** перебор проверяет числа подряд, начиная с 1, на делимость на 7. Внутри цикла нет пауз. Через 500 мс после старта перебор нужно остановить.

**Что сделать:**

1. Перебор выполняет один поток.
2. Через 500 мс основная программа просит этот поток закончить. Поток сам замечает просьбу, выходит из цикла и печатает, сколько чисел проверил. Число любое больше нуля.
3. Строку «Время» печатает основная программа после того, как перебор уже завершился. Общее время — не больше 1000 мс.
4. Процесс завершается сам. Принудительно завершать его нельзя.

```text
Поиск остановлен, проверено чисел: 1399929984
Время: 522 мс
```

## Задача 5. Фоновая статистика

**Ситуация:** основная работа занимает 1000 мс. Параллельно счётчик каждые 300 мс пишет строку статистики с номером. Счётчик крутится без конца; его никто не останавливает и не ждёт его завершения.

**Что сделать:**

1. Счётчик — отдельный поток с бесконечным циклом. Каждые 300 мс он печатает «Статистика: N».
2. Поток счётчика — **daemon** (фоновый): JVM **не ждёт** его при завершении программы (раздел теории «Daemon-потоки программу не задерживают»).
3. Основную работу выполняет основная программа. После неё она одна печатает «Основная работа завершена» и время в миллисекундах.
4. Процесс **сам** заканчивается сразу после этой строки. В выводе успевают «Статистика: 1», «2» и «3»; «Статистика: 4» нет. Общее время — не больше 1200 мс. Принудительно завершать процесс нельзя.

```text
Статистика: 1
Статистика: 2
Статистика: 3
Основная работа завершена (1006 мс)
```

## Задача 6. Контроль платёжного исполнителя

**Ситуация:** платёж проводит один поток. Пока идёт платёж, поток **только ждёт ответ банка**. Это ожидание длится **1000 мс** (как в других задачах: «занимает N мс» — вы сами задаёте эту длительность в коде).

Основная программа **три раза** пишет в журнал состояние потока платежа. Все три строки журнала печатает **основная программа**. Поток платежа в журнал ничего не пишет.

**Хронология (важно соблюдать порядок):**

| Шаг | Когда | Кто печатает | Что в журнале |
|---|---|---|---|
| 1 | Поток платежа **создан**, но работу **ещё не начал** | основная программа | `Создан: …` → ожидается `NEW` |
| 2 | Поток платежа **уже начал** работу; с этого момента прошло **300 мс**; ответ банка **ещё не пришёл** (из 1000 мс прошло только 300) | основная программа | `Ждёт ответа банка: …` → ожидается `TIMED_WAITING` |
| 3 | Поток платежа **полностью закончил** работу (все 1000 мс ожидания банка прошли) | основная программа | `Завершил: …` → ожидается `TERMINATED` |

**Что сделать:**

1. Вместо многоточия подставляется **состояние, которое сообщает JVM** для этого потока. Строки `NEW`, `TIMED_WAITING`, `TERMINATED` в код **готовым текстом не писать**.
2. На шаге 2 проверка должна попасть **между** 300 мс и 1000 мс от старта работы потока платежа. Если проверить слишком рано или когда банк уже «ответил», вторая строка не будет `TIMED_WAITING`.
3. В выводе только эти три строки журнала, без лишних пустых строк и без сообщений от потока платежа.

```text
Создан: NEW
Ждёт ответа банка: TIMED_WAITING
Завершил: TERMINATED
```

## Задача 7. Отчёт дважды за смену

**Ситуация:** за смену отчёт формируют **два раза подряд**: сначала в начале смены, потом в конце. Одно формирование занимает **300 мс**. Алгоритм формирования **один и тот же** — в программе его описывают **один раз** и используют для **обоих** запусков (не копируют одно и то же тело второй раз в коде).

**Хронология (строго по порядку, не параллельно):**

| Шаг | Кто работает | Что происходит | Кто печатает |
|---|---|---|---|
| 1 | поток с названием `report-1` | формирует отчёт **300 мс**, затем заканчивает | этот поток → `Отчёт сформирован, исполнитель: report-1` |
| 2 | поток с названием `report-2` | начинает **только после** шага 1; снова **300 мс**, затем заканчивает | этот поток → `Отчёт сформирован, исполнитель: report-2` |
| 3 | основная программа | оба отчёта уже готовы | основная программа → `Программа завершена без ошибок` |

**Что сделать:**

1. Два запуска — **два разных потока**. Имена потоков: `report-1` и `report-2` (задаются при создании потока).
2. Строку «Отчёт сформирован, исполнитель: …» печатает **сам** поток, который только что формировал отчёт. Вместо многоточия — **название этого потока** (то, которое JVM знает для потока, напечатавшего строку). Строки `report-1` / `report-2` в код **готовым текстом для подстановки в println не писать**.
3. Второй запуск **не начинается**, пока первый поток **полностью** не закончил формирование и не напечатал свою строку.
4. Программа завершается **без исключений**. В выводе ровно три строки, как в образце.

```text
Отчёт сформирован, исполнитель: report-1
Отчёт сформирован, исполнитель: report-2
Программа завершена без ошибок
```

# Тема 12. Практика: синхронизаторы

> **Статус:** практика · **Как сдавать:** код в чат.

---

## Задача 1. Три склада, потом отчёт

**Ситуация:**

Три склада грузятся по **150 мс**. Директор печатает `сводка` только когда все трое закончили.

**Что сделать:**

1. Директор не крутит `join` трёх потоков вручную как единственный способ (используйте одноразовый барьер-счётчик стартовой темы).
2. Печать `сводка` одна, после трёх загрузок.
3. Время меньше 400 мс.

---

## Задача 2. Два круга расчёта

**Ситуация:**

Двое считают. Круг 1: каждый печатает `круг1`, ждут обоих. Круг 2: `круг2`, ждут обоих. Затем `финиш` печатает `main`.

**Что сделать:**

Порядок: обе строки `круг1` раньше любой `круг2`. Затем `финиш`. Состав участников один и тот же, два раунда.

---

## Задача 3. Три окна партнёра

**Ситуация:**

К внешнему API нельзя больше **двух** запросов сразу. Шесть запросов по **100 мс**.

**Что сделать:**

1. Одновременно в «API» не больше двух (пауза 100 мс изображает запрос).
2. Все шесть заканчиваются, `main` печатает `6`.
3. Если пропуск не вернуть — четвёртый запрос повиснет: верните пропуск даже при ошибке.

---

## Задача 4. Участник ушёл

**Ситуация:**

Трое начинают раунд. После первого раунда один **больше не участвует**. Оставшиеся делают второй раунд вдвоём.

**Что сделать:**

1. После раунда 1 три строки `r1`.
2. После раунда 2 две строки `r2`.
3. Программа завершается, нет сломанного барьера.

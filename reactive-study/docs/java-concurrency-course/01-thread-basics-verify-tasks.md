## Ревью

Код **не пишете**.

### Р1. `run()` и `start()` — что в консоли?

Типовой вопрос: *что будет, если вызвать `run()` напрямую, а не `start()`?* (GFG, Baeldung Q2).

```java
public class Main {
    public static void main(String[] args) {
        Thread t = new Thread(() ->
                System.out.println("работаю в потоке: " + Thread.currentThread().getName()));
        t.run();
        t.start();
    }
}
```

1. Сколько строк напечатает программа (если не будет исключения)?
2. Какие **имена потоков** будут в двух строках с «работаю в потоке»?
3. Завершится ли программа нормально?

### Р2. Второй `start()` и daemon

Два фрагмента, как на собеседовании «найди проблему».

**А.**

```java
Thread t = new Thread(() -> System.out.println("ok"));
t.start();
t.start();
```

**Б.**

```java
Thread bg = new Thread(() -> { /* бесконечный цикл */ });
bg.start();
bg.setDaemon(true);
```

Для **А** и **Б** отдельно: что произойдёт при запуске (исключение, поведение JVM)?

### Р3. `join()` и «результат готов»

Типовой сценарий: *главный поток должен дождаться worker и только потом читать результат* (Baeldung / вопросы про `join()`).

```java
static int answer;

public static void main(String[] args) {
    Thread worker = new Thread(() -> {
        try { Thread.sleep(500); } catch (InterruptedException e) { return; }
        answer = 42;
    });
    worker.start();
    System.out.println("Ответ: " + answer);
}
```

Почему на собеседовании скажут, что вывод **ненадёжен**? Что должно измениться по **смыслу** (без указания конкретного API в ответе — своими словами)?

## Самостоятельное выполнение

Класс с `main`, с нуля. Сюжеты — те же классы вопросов, что на интервью, но **новая постановка**.

### С1. Кто выполняет задачу?

На собеседовании часто просят: *создайте поток и покажите, что `run()` выполняется не в `main`* (вариант Baeldung Q2).

**Ситуация:** один worker с именем `worker`. Он печатает одну строку:

```text
worker выполняет задачу
```

**Что сделать:**

1. В строке должно быть видно **имя потока** `worker` (как JVM его знает для этого потока), а не слово `main`.
2. Строку печатает **сам** worker.
3. В выводе **нет** исключений.

### С2. JVM и daemon

Типовой вопрос: *daemon не держит JVM* (Baeldung Q5).

**Ситуация:** `main` печатает `Конец` через **300 мс** после старта. Параллельно фоновый поток каждые **100 мс** печатает `Фон: N` (N = 1, 2, 3, …), бесконечно.

**Что сделать:**

1. Фон — **daemon**.
2. После `Конец` процесс **сам** завершается меньше чем за **500 мс**.
3. В выводе есть `Фон: 1` и `Фон: 2`, строки `Фон: 3` **нет**.

```text
Фон: 1
Фон: 2
Конец
```

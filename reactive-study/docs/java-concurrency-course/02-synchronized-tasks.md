## Правила

- Каждая задача — отдельный класс с методом `main`, написанный с нуля.
- Используются только средства тем 01 и 02.
- В блоке «Что сделать» сказано, кто печатает и какой итог нужен. Каким ключевым словом это сделать, в условии не сказано.
- Решение считается верным, если итог **один и тот же** при нескольких запусках.

## Задача 1. Два кассира, одна касса

**Ситуация:**

Два кассира пробивают покупки в одну кассу. Каждый пробивает **50 000** покупок по 1 рублю.

**Что сделать:**

1. Два потока одновременно увеличивают **одну** сумму кассы.
2. Основная программа печатает итог **после** того, как оба кассира закончили.
3. В выводе ровно одно число: **100000**. Число 100000 в код как готовый ответ не вписывать — оно должно получиться из сложения.

**Ожидаемый результат:**

```text
100000
```

Число одно и то же при каждом запуске.

## Задача 2. Списание с баланса

**Ситуация:**

На счёте **1000** рублей. Два платежа по **700** идут одновременно. Списать можно только если на счёте хватает денег. Второй платёж, которому не хватило, печатает отказ.

**Что сделать:**

1. Два потока одновременно пытаются списать: первый — 700, второй — 700.
2. После обоих попыток баланс **300**. Один платёж прошёл, второй получил отказ.
3. Основная программа печатает баланс и сколько платежей прошло. Печать — только после обеих попыток.

**Ожидаемый результат** (порядок строк «списано / отказ» любой):

```text
списано 700
отказ 700
баланс 300
успешных 1
```

При каждом запуске успешных платежей ровно 1, баланс ровно 300.

## Задача 3. Два независимых склада

**Ситуация:**

Склад Москвы и склад Казани считают приход **независимо**. На каждом складе один поток делает **20 000** приёмок по 1 единице.

**Что сделать:**

1. Два склада — два отдельных объекта с собственным остатком.
2. Потоки работают одновременно: один только с Москвой, другой только с Казанью.
3. Основная программа печатает оба остатка после обеих приёмок.

**Ожидаемый результат:**

```text
Москва 20000
Казань 20000
```

Оба числа стабильны при каждом запуске. Время работы — заметно меньше, чем если бы склады ждали друг друга по очереди (на практике оба потока идут параллельно).

## Задача 4. Общий журнал смен

**Ситуация:**

У смены два рабочих места (`shiftA` и `shiftB` — разные объекты). Оба пишут в **один общий** журнал смен: сколько раз открыли кассу. Каждый объект делает **40 000** записей.

**Что сделать:**

1. Журнал — одно общее поле на весь класс, не отдельное у каждого рабочего места.
2. Два потока вызывают запись через **разные** объекты `shiftA` и `shiftB`.
3. Основная программа печатает число записей после обеих смен. Ожидается **80000**.

**Ожидаемый результат:**

```text
80000
```

Число стабильно при каждом запуске. Если защищать только «своё рабочее место», итог будет меньше.

## Задача 5. Приёмка и отгрузка не мешают друг другу

**Ситуация:**

На площадке два независимых счётчика: `in` (приёмка) и `out` (отгрузка). Их **никогда** не складывают в одной операции. Приёмка делает **30 000** единиц, отгрузка — **30 000**. Нужно, чтобы приёмка и отгрузка шли **одновременно**, не стоя в одной очереди.

**Что сделать:**

1. Один поток только увеличивает `in`, другой — только `out`.
2. Оба счётчика в конце равны **30000**.
3. Пока один поток пишет в `in`, второй **не ждёт** его, чтобы писать в `out` (они не делят одну очередь).

**Ожидаемый результат:**

```text
in 30000
out 30000
```

Оба числа стабильны. Если оба счётчика закрыть одним общим замком на весь объект — итог тоже будет верный, но потоки будут мешать друг другу без нужды. Нужно независимое обновление.

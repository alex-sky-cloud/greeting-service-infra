## Задание 1 — жалоба от трёх клиентов

**Ситуация:** в поддержку пришла пачка обращений. Менеджер дал список id клиентов: **1, 2 и 3** — это Ann, Bob и Carol, самые первые пользователи системы. Нужно быстро вытащить их из базы, чтобы сверить данные перед ответом.

**Задача:** найти этих трёх пользователей в таблице `users`. Показать **id** и **имя** (`full_name`).  
Подсказка: id уже известны списком — удобнее один оператор **`IN`**, чем три раза писать `OR`.  
Отсортируйте по id.

## Задание 2 — рассылка на «старый» домен

**Ситуация:** маркетинг готовит письмо только для **ранних демо-пользователей**. У них email на домене **`@example.com`** (не на `@load.reactive-study.test`, куда потом залили нагрузочных пользователей).

**Задача:** найти всех таких пользователей — id и email.  
Подсказка: email **заканчивается** на определённый текст → шаблон с **`LIKE`** и `%`.

## Задание 3 — заказы «ещё в работе»

**Ситуация:** складу нужен список заказов, которые **ещё не завершены и не отменены** — то есть не в статусах `delivered` и `cancelled`. Это заказы, с которыми ещё что-то предстоит сделать.

**Задача:** из таблицы `orders` показать **id** и **status** таких заказов. Достаточно **10** штук для просмотра, по id.  
Подсказка: «статус **не** из этого списка» → **`NOT IN`**.

## Задание 4 — первые тестовые пользователи

**Ситуация:** после нагрузочного теста аналитик просит выгрузить «первую пятёрку» load-пользователей — это пользователи с id **с 5 по 9** включительно (Load User 5 … Load User 9).

**Задача:** id и full_name этих пятерых. Показать **сначала с большим id** (9, 8, 7…).  
Подсказка: закрытый диапазон «от и до включительно» → **`BETWEEN`**.

## Задание 5 — крупные заказы на проверке

**Ситуация:** финансовый контроль ищет **подозрительно крупные** заказы, которые ещё **не ушли в доставку**, но уже висят в обработке: статус **`pending`** или **`processing`**, и сумма заказа **больше 1000**.

**Задача:** id, status и amount таких заказов — **10** штук для ручной проверки, по id.  
Подсказка: «один из двух статусов **и** одновременно большая сумма» — здесь нужны **`OR`**, **`AND`** и **скобки**, иначе условие прочитается неверно.

---

## Задание 6 — заказы с привязкой к каталогу

**Ситуация:** в старых заказах поле `product_id` иногда пустое (заказ по свободному названию). Каталогу нужны только заказы, где товар **уже привязан** к строке в таблице `products` — то есть `product_id` **заполнен**.

**Задача:** id, product_id и status для таких заказов — **5** примеров, по id.  
Подсказка: «значение есть / нет» проверяют не через `=`, а через **`IS NOT NULL`**.

## Задание 1 — обращение по заказу

**Ситуация:** в поддержку пришёл звонок: «Я оформил заказ **100001**, проверьте статус». Оператору нужны **id заказа**, **имя клиента**, **email** и **статус** заказа — одной строкой.

**Задача:** найти этот заказ и показать перечисленные поля.

---

## Задание 2 — карточка постоянного клиента

**Ситуация:** менеджер открывает карточку **Ann Smith** (`users.id = 1`). Нужен список **всех её заказов**: id заказа, сумма, статус. Сначала **новые** заказы (больший id выше).

**Задача:** имя клиента и данные по каждому его заказу — **10** строк для просмотра.

---

## Задание 3 — спящие клиенты

**Ситуация:** маркетинг ищет пользователей, которые **есть в системе**, но **ни одного заказа** не оформили — для email-кампании «вернитесь в магазин».

**Задача:** **сколько всего** таких клиентов в базе (одно число).

---

## Задание 4 — SMS по доставленным

**Ситуация:** после доставки отправляют SMS-опрос. Нужны **5** последних (по id заказа) заказов со статусом **`delivered`**: id заказа, email клиента, сумма.

**Задача:** выгрузка для рассылки — 5 строк.

---

## Задание 5 — заказы «в работе» с контактами

**Ситуация:** складу нужен список заказов, которые **ещё не завершены и не отменены** (не `delivered`, не `cancelled`), вместе с **именем** покупателя — чтобы звонить при задержке.

**Задача:** id заказа, имя клиента, статус, сумма — **10** строк, по id заказа.

---

## Задание 6 — учебные клиенты без покупок

**Ситуация:** QA проверяет учебные данные миграции V12 — клиенты `join-demo-no-orders-*@example.com` должны быть **без заказов**.

**Задача:** email, имя клиента, id заказа (если есть) — для всех четырёх учебных адресов.  
Ожидается, что столбец заказа **пустой** — но это проверите вы по результату.

---

## Задание 7 — выручка по имени клиента

**Ситуация:** бухгалтерия просит **общую сумму** всех заказов клиента **Bob Jones** (`users.id = 2`) и его **полное имя** в одной строке отчёта.

**Задача:** имя клиента и итоговая сумма `amount` по всем его заказам.

---

## Задание 8 — крупные заказы: кто покупатель

**Ситуация:** antifraud просматривает заказы **от 1500** включительно — нужно видеть **имя** и **email** покупателя, не только `user_id`.

**Задача:** id заказа, имя, email, сумма — **10** самых крупных по сумме (при равенстве — меньший id заказа выше).

---

## Задание 9 — топ клиентов по числу заказов

**Ситуация:** программа лояльности — нужны **5** клиентов с **наибольшим** числом заказов: имя и количество заказов.

**Задача:** `full_name` и число заказов — 5 строк; при равном количестве — имя по алфавиту (A→Z).

---

## Задание 10 — «тяжёлые» покупатели

**Ситуация:** VIP-отдел интересуют клиенты, у которых **больше 25** заказов — для персонального менеджера.

**Задача:** id клиента, имя, **сколько** у него заказов. Только такие «тяжёлые» клиенты.  
Сортировка: сначала с **большим** числом заказов.

---

## Задание 11 — ранние пользователи example.com

**Ситуация:** нужна сводка по **первым трём** демо-пользователям (id **1, 2, 3** — Ann, Bob, Carol): сколько заказов у каждого и **суммарная** трата.

**Задача:** id клиента, имя, количество заказов, общая сумма заказов.  
Сортировка по id (1 → 2 → 3).

---

## Задание 12 — сравнение двух клиентов

**Ситуация:** аналитик сравнивает учебного клиента **с заказами** и **без**:

- `join-demo-single-order@example.com`
- `join-demo-no-orders-1@example.com`

**Задача:** email, имя, id заказа, сумма заказа — все строки, которые получатся при «полном» соединении клиента с его заказами (если заказов нет — клиент всё равно должен быть виден).  
Сортировка: по email, затем по id заказа (пустые в начале группы).

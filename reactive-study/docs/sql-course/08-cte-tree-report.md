# Дерево компании: path, отступы и порядок строк

Задача: вывести **все** отделы, начиная с корня «Компания», в виде «блока» — как на скриншоте: слева отступы по уровню, строки идут сверху вниз по дереву, а не просто по `level`, потом по `id`.

Таблица `departments`, база `reactive_study`.

Три способа вывести **то же дерево** из 13 отделов (обход в глубину, порядок веток совпадает):

| Способ | Что копим в рекурсии | Как сортировать | Где разбор |
|---|---|---|---|
| массив `path` | `array[id]`, дальше `parent.path \|\| child.id` | `ORDER BY path` | этот файл |
| `SEARCH DEPTH FIRST` | только `level`; `ord` добавляет PostgreSQL | `ORDER BY ord` | [`08-cte-tree-search.md`](08-cte-tree-search.md) |
| текстовый `path` | `d.name`, дальше `tree.path \|\| ' / ' \|\| child.name` | `ORDER BY path` | [`08-cte.md`](08-cte.md) — [Путь от корня до отдела](08-cte.md#путь-от-корня-до-отдела) |

Рекурсия по `JOIN` и волнам **одна и та же**; меняется только столбец для порядка и отображения.

---

## Полный запрос с комментариями

Сначала запрос целиком. Комментарии `--` поясняют, что делает каждая часть.

```sql

WITH RECURSIVE subtree AS (          -- рекурсивный CTE: имя subtree ссылается на себя ниже

    -- СТАРТОВАЯ ЧАСТЬ: один раз, корень дерева
    SELECT id,
           parent_id,
           name,
           1 AS level,               -- уровень отчёта: корень = 1
           array[id] AS path         -- путь от корня: массив id, начинается с {1}
    FROM departments
    WHERE name = 'Компания'          -- стартовая строка по имени, не по «магическому» id

    UNION ALL                        -- граница: ниже только повторяющаяся часть

    -- РЕКУРСИВНАЯ ЧАСТЬ: ищем детей для строк текущей рабочей таблицы subtree
    SELECT child.id,
           child.parent_id,
           child.name,
           parent.level + 1,         -- ребёнок на один уровень глубже родителя из рабочей таблицы
           parent.path || child.id   -- путь: к массиву предков дописать id ребёнка
    FROM departments child           -- child = псевдоним всей таблицы departments
    JOIN subtree parent              -- parent = псевдоним текущей рабочей таблицы subtree
      ON parent.id = child.parent_id -- связь «родитель из рабочей таблицы → строка-ребёнок в departments»
)

-- Обычный SELECT после CTE: рекурсия уже завершена, читаем готовый subtree
SELECT id,
       parent_id,
       repeat('    ', level - 1) || name AS name,  -- отступ: 4 пробела на каждый уровень ниже корня
       level
FROM subtree
ORDER BY path;                       -- порядок «как в дереве»: по цепочке id от корня до листа
```

Итоговый вид результата (колонка `name` с отступами, без служебной колонки `path`):

| id | parent_id | name | level |
|---:|---:|---|---:|
| 1 | NULL | Компания | 1 |
| 2 | 1 | &nbsp;&nbsp;&nbsp;&nbsp;Коммерческий департамент | 2 |
| 5 | 2 | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Отдел продаж | 3 |
| 6 | 2 | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Отдел маркетинга | 3 |
| 13 | 6 | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Группа аналитики | 4 |
| 3 | 1 | &nbsp;&nbsp;&nbsp;&nbsp;Логистический департамент | 2 |
| 7 | 3 | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Склад | 3 |
| 8 | 3 | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Доставка | 3 |
| 4 | 1 | &nbsp;&nbsp;&nbsp;&nbsp;Технический департамент | 2 |
| 9 | 4 | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Отдел разработки | 3 |

Порядок строк совпадает с `ORDER BY path`: сначала вся ветка `{1,2,…}`, затем `{1,3,…}`, затем `{1,4,…}`.

## Как по тексту запроса найти старт и рекурсию

| Место в запросе | Роль |
|---|---|
| `WITH RECURSIVE subtree AS (...)` | разрешает самоссылку `JOIN subtree` внутри определения `subtree` |
| запрос **до** первого `UNION ALL` внутри `subtree` | стартовая часть, выполняется **один раз** |
| запрос **после** `UNION ALL`, где есть `JOIN subtree` | повторяющаяся часть |
| `SELECT … FROM subtree ORDER BY path` после `)` | обычный итоговый запрос, рекурсии уже нет |

## Часть 1. Старт без `path` и без отступов

Корень по имени:

```sql

SELECT id, parent_id, name
FROM departments
WHERE name = 'Компания';
```

| id | parent_id | name |
|---:|---:|---|
| 1 | NULL | Компания |

`parent_id` пустой — это корень дерева отделов.

---

## Часть 2. Зачем столбец `path`

`ORDER BY level, id` группирует все отделы одного уровня подряд, но **перемешивает ветки**: сначала все «уровень 2», потом все «уровень 3», без связи «родитель сразу над детьми».

Нужен столбец, который запоминает цепочку `id` от корня до текущей строки. В PostgreSQL для этого удобен массив целых:

- у «Компании» `path = {1}`;
- у «Коммерческого департамента» `path = {1,2}`;
- у «Группы аналитики» `path = {1,2,6,13}`.

Сравнение массивов при `ORDER BY path` даёт порядок обхода: родитель всегда выше своих потомков в списке, ветка не рвётся.

Стартовая часть задаёт первый элемент пути:

```sql

SELECT id, parent_id, name, 1 AS level, array[id] AS path
FROM departments
WHERE name = 'Компания';
```

| id | parent_id | name | level | path |
|---:|---:|---|---:|---|
| 1 | NULL | Компания | 1 | {1} |

`array[id]` — масс из одного элемента: номер строки корня.

## Часть 3. Как дописывается `path` в рекурсии

Повторяющаяся часть:

```sql

SELECT child.id,
       child.parent_id,
       child.name,
       parent.level + 1,
       parent.path || child.id
FROM departments child
JOIN subtree parent
  ON parent.id = child.parent_id
```

- `parent.path` — массив предков из **текущей** строки рабочей таблицы;
- `||` для массивов в PostgreSQL **склеивает** массивы: `{1,2} || 5` → `{1,2,5}`;
- `child.id` — номер найденного ребёнка в `departments`.

На **одной** паре родитель → ребёнок PostgreSQL вычисляет новый массив и кладёт его в строку результата повтора (отдельного «хранилища» для `||` нет):

| parent.path (из рабочей таблицы) | child.id | parent.path \|\| child.id |
|---|---:|---|
| {1} | 2 | {1,2} |
| {1,2} | 5 | {1,2,5} |
| {1,4} | 9 | {1,4,9} |

Учебный `SELECT` без рекурсии (только склейка массива):

```sql

SELECT parent.path || child.id AS path
FROM (SELECT ARRAY[1, 2] AS path) parent
CROSS JOIN (SELECT 5 AS id) child;
```

| path |
|---|
| {1,2,5} |

Текстовый путь через `|| ' / ' ||` — в [`08-cte.md`](08-cte.md#путь-от-корня-до-отдела); здесь `||` склеивает **массив и число**, не строки с пробелами.

### Повтор 4: остановка

Рабочая таблица: `11`, `12`, `13`. У этих `id` в `departments` нет строк с таким `parent_id`.

Повторяющаяся часть возвращает **пустую** таблицу.

**Накопленный результат не меняется** (те же 13 строк).

**Новая рабочая таблица пуста** → рекурсия закончена.

Отдельного `WHERE` для выхода нет: остановка там же, где у листьев нет детей.

## Часть 5. Внешний SELECT: отступы и сортировка

Рекурсия уже построила все 13 строк с колонками `id`, `parent_id`, `name`, `level`, `path`.

### `repeat('    ', level - 1) || name`

- `level - 1` — сколько «ступеней» ниже корня;
- `repeat('    ', n)` — строка из `n` раз по четыре пробела;
- `|| name` — к отступу приклеивается название отдела.

| level | repeat('    ', level - 1) | эффект |
|---:|---|---|
| 1 | `` (0 пробелов) | без отступа |
| 2 | `    ` | один блок |
| 3 | `        ` | два блока |
| 4 | `            ` | три блока |

Отступ только для **отображения** в колонке `name`. Столбцы `id`, `parent_id`, `level` не меняются.

### `ORDER BY path`

Сортировка по массиву `path`, не по `name`.

Почему «Отдел тестирования» (`10`) идёт **после** групп `11` и `12`: пути `{1,4,10}` и `{1,4,9,11}` сравниваются по элементам массива; ветка через `9` с более длинным путём к листьям `11`/`12` в этом порядке оказывается между `{1,4,9}` и `{1,4,10}`.

Для отладки можно временно вывести `path`:

```sql

SELECT id, parent_id, name, level, path
FROM subtree
ORDER BY path;
```

## Часть 6. Чем этот запрос отличается от «только поддерево департамента»

| | Дерево от `Компания` (этот документ) | Поддерево от департамента (часть 7.1) |
|---|---|---|
| Старт | `WHERE name = 'Компания'` | `WHERE id = 4` или через `target` |
| Охват | все 13 отделов | только ветка технического департамента |
| `path` | да, для порядка строк | в базовом примере не было |
| Отступы в `name` | `repeat` во внешнем SELECT | в базовом примере не было |

## Задание 1 — строка дашборда по заказам

**Ситуация:** управляющий открывает главный экран магазина. Ему нужна одна строка: сколько заказов в магазине всего, сколько уже доставлено покупателю, сколько отменено, и сколько денег принесли только доставленные заказы.

**Что получить:** одна строка.

- Поля:
  - сколько заказов всего;
  - сколько заказов доставлено;
  - сколько заказов отменено;
  - сумма денег только по доставленным заказам.

## Задание 2 — все статусы заказов в одной строке

**Ситуация:** операционный директор просит разложить все заказы по статусам, но не списком строк, а одной строкой отчёта. В каждом столбце — свой статус.

**Что получить:** одна строка.

- Поля:
  - сколько заказов ждут обработки;
  - сколько заказов сейчас собирают;
  - сколько заказов уже отправлено покупателю;
  - сколько заказов доставлено;
  - сколько заказов отменено.

Статусы в данных такие: `pending`, `processing`, `shipped`, `delivered`, `cancelled`.

## Задание 5 — средняя сумма доставленного заказа

**Ситуация:** маркетинг считает средний чек только по тем заказам, которые покупатель уже получил. Остальные статусы в среднее не входят. Рядом нужно видеть, из скольких доставленных заказов это среднее собрано.

**Что получить:** одна строка.

- Поля:
  - средняя сумма доставленного заказа, округлённая до двух знаков после запятой;

## Задание 6 — крупные заказы внутри каждого статуса

**Ситуация:** аналитик смотрит каждый статус заказа отдельно. Крупным считается заказ дороже **1500**. Для статуса нужно и общее число заказов, и сколько среди них крупных, и сколько денег дают только крупные.

**Что получить:** по одной строке на каждый статус заказа.

- Поля:
  - статус заказа;
  - сколько заказов имеют этот статус;
  - сколько заказов с этим статусом дороже **1500**;
  - сумма денег только по заказам с этим статусом дороже **1500**.

Сортировать по статусу заказа, от A к Z.

## Задание 7 — доля успешных списаний

**Ситуация:** платёжный отдел смотрит, как часто деньги списываются с первой или любой попытки. Каждая строка журнала оплат — одна попытка списать деньги по заказу. Число попыток — это число строк. Столбец `id` только нумерует строку во всей таблице, по нему отчёт не строят. Столбец `attempt_no` в этом отчёте не нужен.

В столбце `status` записано, чем закончилась попытка.

- `success` значит, что деньги списались.
- `failed` значит, что списание не удалось.

**Что получить:** одна строка.

- Поля:
  - сколько попыток списания всего;
  - сколько попыток закончились статусом `success`;
  - сколько попыток закончились статусом `failed`;
  - доля успешных попыток в процентах, округлённая до двух знаков после запятой.

## Задание 8 — первая неудача и третья удача

**Ситуация:** поддержка разбирает повторные списания. Нужно два числа в одной строке: сколько раз самое первое списание по заказу не прошло и сколько раз деньги списались только с третьей попытки.

Каждая строка журнала оплат — одна попытка списать деньги по заказу. Число попыток — это число строк. Столбец `id` только нумерует строку. Столбец `attempt_no` показывает, какая это попытка у одного заказа: первая, вторая или третья.

- Если по заказу это первая попытка списания, в `attempt_no` стоит `1`.
- Если по тому же заказу платили ещё раз, в `attempt_no` стоит `2`. Если ещё раз — `3`.
- `success` значит, что деньги списались.
- `failed` значит, что списание не удалось.

Это не число карт. В журнале карты нет: клиент мог платить одной картой несколько раз.

**Что получить:** одна строка.

- Поля:
  - сколько попыток с `attempt_no` равным `1` закончились статусом `failed`;
  - сколько попыток с `attempt_no` равным `3` закончились статусом `success`.

## Задание 9 — первая и повторные попытки по статусу

**Ситуация:** руководитель платежей хочет видеть статусы списания рядом с тем, с какой попытки по заказу пришла эта строка. Первая попытка — это ещё не повтор. Повтор — вторая или третья попытка по тому же заказу.

Каждая строка журнала оплат — одна попытка списать деньги по заказу. Число попыток — это число строк. Столбец `id` только нумерует строку. Столбец `attempt_no` показывает, какая это попытка у одного заказа.

- Если по заказу это первая попытка списания, в `attempt_no` стоит `1`. Такую попытку считают первой.
- Если по тому же заказу платили ещё раз, в `attempt_no` стоит `2` или `3`. Такую попытку считают повторной.
- `success` значит, что деньги списались.
- `failed` значит, что списание не удалось.

**Что получить:** по одной строке на каждый статус попытки.

- Поля:
  - статус попытки;
  - сколько попыток имеют этот статус;
  - сколько из этих попыток являются первой попыткой по заказу;
  - сколько из этих попыток являются второй или третьей попыткой по заказу.

Сортировать по статусу попытки, от A к Z.

## Задание 10 — деньги по статусу списания

**Ситуация:** финансист смотрит не штуки попыток, а деньги. Для каждого исхода списания нужна общая сумма и отдельно сумма только по повторным попыткам: когда по заказу это уже не первое списание.

Каждая строка журнала оплат — одна попытка списать деньги по заказу. Сумма попытки лежит в поле суммы. Столбец `id` только нумерует строку. Столбец `attempt_no` показывает, какая это попытка у одного заказа.

- Если по заказу это первая попытка списания, в `attempt_no` стоит `1`. Её сумму в столбец повторных денег не кладут.
- Если по тому же заказу платили ещё раз, в `attempt_no` стоит `2` или `3`. Сумму таких попыток кладут в столбец повторных денег.
- `success` значит, что деньги списались.
- `failed` значит, что списание не удалось.

**Что получить:** по одной строке на каждый статус попытки.

- Поля:
  - статус попытки;
  - сумма всех попыток с этим статусом;
  - сумма только тех попыток с этим статусом, у которых `attempt_no` равен `2` или `3`.

Сортировать по статусу попытки, от A к Z.

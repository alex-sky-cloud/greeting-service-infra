# Тема 09 — практические задания

> **Статус:** практика после интервью · **Проверка:** присылайте SQL в чат, семантика проверяется на базе

В начале сессии:

```sql

SET search_path TO reactive_study;
```

Пришлите запросы блоками: **1–4**, затем **5–8**, затем **9–12**, затем **13–15**.

Задачи проверяют оконные функции. Конструкции из тем 01–08 можно использовать там, где они нужны по смыслу.

## Как читать таблицы

**Сотрудники и отделы**

- В `employees` одна строка — один сотрудник.
- `employees.id` — номер сотрудника.
- `employees.department_id` — номер его отдела.
- `employees.manager_id` — номер непосредственного начальника.
- `employees.full_name` — имя.
- `employees.salary` — зарплата.
- В `departments.id` — номер отдела, в `departments.name` — название.

**Заказы**

- В `orders` одна строка — один заказ.
- `orders.id` — номер заказа.
- `orders.user_id` — номер клиента.
- `orders.amount` — сумма.
- `orders.status` — статус.
- `orders.created_at` — время создания.

**Попытки оплаты**

- В `payment_attempts` одна строка — одна попытка списать деньги по заказу.
- `order_id` — номер заказа.
- `attempt_no` — номер попытки внутри заказа.
- `status` — результат попытки: `success` или `failed`.
- `amount` — сумма попытки.
- `created_at` — время попытки.

## Задание 1 — зарплата и средняя по компании

**Ситуация:** руководитель готовится к пересмотру зарплат и хочет видеть каждого сотрудника на фоне всей компании.

**Что получить:** по одной строке на каждого сотрудника.

- Имя сотрудника.
- Его зарплата.
- Средняя зарплата по всем 15 сотрудникам.
- Разница: зарплата сотрудника минус средняя по компании.
- Среднюю и разницу округлить до двух знаков.

---

## Задание 2 — сравнение со своим отделом

**Ситуация:** HR сравнивает сотрудника не со всей компанией, а только с людьми из его отдела.

**Что получить:** по одной строке на каждого сотрудника.

- Название отдела.
- Имя сотрудника.
- Его зарплата.
- Средняя зарплата в этом отделе.
- Разница: зарплата сотрудника минус средняя его отдела.
- Среднюю и разницу округлить до двух знаков.

---

## Задание 3 — место сотрудника по зарплате

**Ситуация:** финансовый директор просит единый список зарплат от самой большой к самой маленькой.

**Что получить:** все 15 сотрудников.

- Порядковый номер в списке, начиная с 1.
- Номер сотрудника.
- Имя сотрудника.
- Зарплата.
- Если зарплаты равны, первым должен идти сотрудник с меньшим номером.
- Строки отчёта расположить по присвоенному порядковому номеру.

## Задание 4 — рейтинг руководителей

**Ситуация:** HR составляет рейтинг начальников по числу прямых подчинённых. Начальники с одинаковым числом людей должны занимать одинаковое место. Следующий начальник получает место с учётом всех, кто стоит выше: если трое делят первое место, следующий получает четвёртое.

**Что получить:** начальники, у которых есть хотя бы один прямой подчинённый.

- Имя начальника.
- Число прямых подчинённых.
- Место в рейтинге.
- Начать с наибольшего числа подчинённых.

## Задание 5 — самый высокооплачиваемый сотрудник отдела

**Ситуация:** HR просит одного представителя с наибольшей зарплатой из каждого отдела, где есть сотрудники.

**Что получить:** по одному сотруднику из каждого непустого отдела.

- Название отдела.
- Номер сотрудника.
- Имя сотрудника.
- Зарплата.
- Если максимальная зарплата одинакова у нескольких людей, выбрать сотрудника с меньшим номером.

## Задание 6 — два сотрудника из каждого отдела

**Ситуация:** для выборочной проверки зарплат нужны не более двух наиболее высокооплачиваемых сотрудников каждого отдела.

**Что получить:** не больше двух строк на отдел.

- Название отдела.
- Имя сотрудника.
- Зарплата.
- Порядковый номер сотрудника внутри отдела.
- При одинаковой зарплате первым идёт сотрудник с меньшим номером.
- Если в отделе один человек, вывести одну строку.

## Задание 7 — три дорогих заказа каждого статуса

**Ситуация:** операционный менеджер проверяет самые дорогие заказы отдельно в каждом статусе.

**Что получить:** не больше трёх заказов на каждый статус.

- Статус заказа.
- Номер заказа.
- Сумма заказа.
- Позиция заказа внутри своего статуса.
- Сначала большая сумма; при одинаковой сумме — меньший номер заказа.

## Задание 8 — последний заказ каждого клиента

**Ситуация:** служба поддержки хочет открыть последний заказ каждого клиента.

**Что получить:** по одной строке на каждого клиента, у которого есть заказ.

- Номер клиента.
- Номер его последнего заказа.
- Статус последнего заказа.
- Сумма последнего заказа.
- Время создания последнего заказа.
- Если у клиента два заказа с одинаковым временем, последним считается заказ с большим номером.

## Задание 9 — накопленная сумма заказов клиента

**Ситуация:** в истории клиента рядом с каждым заказом показывают общую сумму созданных им заказов с первого по текущий. Учитываются все статусы; это не сумма фактически оплаченных покупок.

**Что получить:** все заказы.

- Номер клиента.
- Номер заказа.
- Время создания.
- Сумма заказа.
- Накопленная сумма заказов этого клиента до текущего заказа включительно.
- Внутри клиента заказы идут по времени создания, при одинаковом времени — по номеру заказа.

---

## Задание 10 — накопительная сумма заказов по дням

**Ситуация:** операционный дашборд показывает, как растёт сумма созданных заказов день за днём. Учитываются все статусы.

**Что получить:** по одной строке на каждую дату, встречающуюся в заказах.

- Дата заказа.
- Число заказов за эту дату.
- Сумма заказов за эту дату.
- Сумма заказов от первой даты до текущей включительно.
- Даты расположить от ранней к поздней.

---

## Задание 11 — средняя дневная сумма заказов за семь дат

**Ситуация:** аналитик сглаживает дневную сумму всех созданных заказов, чтобы разовый скачок не искажал график. Учитываются все статусы.

**Что получить:** по одной строке на дату.

- Дата.
- Сумма заказов за дату.
- Средняя дневная сумма за текущую дату и шесть предыдущих дат, представленных в отчёте.
- Для начала периода использовать только уже наступившие даты из отчёта.
- Среднее округлить до двух знаков.

## Задание 12 — предыдущая попытка оплаты

**Ситуация:** платёжная команда сравнивает каждую попытку с предыдущей попыткой того же заказа.

**Что получить:** попытки только тех заказов, у которых было больше одной попытки.

- Номер заказа.
- Номер попытки.
- Текущий статус.
- Статус предыдущей попытки того же заказа.
- У первой попытки предыдущий статус пустой.
- Попытки внутри заказа расположить по номеру попытки.

---

## Задание 13 — время между попытками

**Ситуация:** платёжная команда проверяет, сколько минут проходит между повторными попытками одного заказа.

**Что получить:** только вторые и последующие попытки заказов.

- Номер заказа.
- Номер попытки.
- Время текущей попытки.
- Время предыдущей попытки.
- Интервал между ними в минутах, включая дробную часть.
- Число минут округлить до двух знаков.

---

## Задание 14 — доля статуса в заказах

**Ситуация:** на дашборде нужна доля каждого статуса среди всех заказов.

**Что получить:** по одной строке на статус.

- Статус.
- Число заказов с этим статусом.
- Общее число заказов.
- Доля статуса в процентах от общего числа заказов.
- Долю округлить до двух знаков.

## Задание 15 — перерыв между заказами клиента

**Ситуация:** CRM ищет интервалы между покупками клиента.

**Что получить:** все заказы.

- Номер клиента.
- Номер заказа.
- Время заказа.
- Время предыдущего заказа этого клиента.
- Интервал между текущим и предыдущим заказом.
- У первого заказа клиента предыдущее время и интервал пустые.
- Внутри клиента порядок задаётся временем, а при одинаковом времени — номером заказа.

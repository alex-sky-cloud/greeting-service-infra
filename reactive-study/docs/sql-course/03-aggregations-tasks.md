## Задание 1 — дашборд руководства

**Ситуация:** утренний соз созванивается с финансами. Нужны два числа по **всем** заказам в системе: сколько заказов всего и какая **общая сумма** всех заказов (выручка «гross», без вычетов).

**Задача:** один запрос, одна строка результата — **общее количество заказов** и **общая сумма** поля `amount`.

---

## Задание 2 — нагрузка по статусам

**Ситуация:** операционный менеджер смотрит, как распределены заказы по этапам жизненного цикла.

**Задача:** для каждого значения `status` показать **количество заказов**.  
Сначала статусы с **наибольшим** числом заказов, при равенстве — по алфавиту **status** (A→Z).

---

## Задание 3 — средний чек по статусам

**Ситуация:** аналитик сравнивает «типичную» сумму заказа на разных этапах — не путает ли склад мелочь с крупными отправлениями.

**Задача:** `status` и **среднее** значение `amount` по каждому статусу.  
Сортировка: от **большего** среднего чека к **меньшему**.

---

## Задание 4 — выручка только доставленных

**Ситуация:** в отчёт для инвесторов попадает только фактически **завершённая** доставка — статус `delivered`.

**Задача:** один запрос, одна строка — **сколько** таких заказов и **сумма** их `amount`.

---

## Задание 5 — заказы с привязкой к каталогу

**Ситуация:** команда каталога хочет понять, какая доля заказов уже связана с карточкой товара (`product_id` заполнен), а сколько оформлено «свободным текстом».

**Задача:** одна строка с двумя столбцами:

| Столбец | Смысл |
|---|---|
| `with_catalog` | заказов, где `product_id` **не** NULL |
| `total_orders` | заказов **всего** |

---

## Задание 6 — «тяжёлые» статусы

**Ситуация:** планируют штат поддержки по статусам. Интересуют только «крупные» группы — где заказов **больше 18 000**.

**Задача:** `status` и **количество** заказов только для таких статусов.  
Сортировка по убыванию количества.

---

## Задание 7 — крупные заказы на проверке

**Ситуация:** antifraud смотрит **крупные** заказы (сумма **от 1000** включительно). Нужны статусы, где **средний** чек среди уже отфильтрованных заказов **не ниже 1500**.

**Задача:** `status` и **средний** `amount` по подходящим группам.  
Сортировка: сначала статус с **наибольшим** средним чеком.

---

## Задание 8 — самый ценный клиент

**Ситуация:** CRM готовит персональное предложение для клиента с **максимальной** суммарной тратой по всем заказам.

**Задача:** **одна** строка — `user_id` этого клиента и его **общая сумма** всех заказов (`amount`).

---

## Задание 9 — диапазон сумм по статусам

**Ситуация:** SLA согласуют с реальностью — для каждого статуса нужны **минимальная** и **максимальная** сумма заказа.

**Задача:** `status`, **минимальный** и **максимальный** `amount` по группе.  
Сортировка по `status` по алфавиту (A→Z).

---

## Задание 10 — самые активные покупатели

**Ситуация:** программа лояльности — топ клиентов по **частоте** покупок (не по сумме).

**Задача:** **5** строк — `user_id` и **сколько заказов** у каждого.  
Клиенты с **наибольшим** числом заказов; при равенстве — **меньший** `user_id` выше.

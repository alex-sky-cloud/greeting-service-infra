## Правила

- Класс решения: `reactorcourse/t12/T12LifecycleTasks`. Тест: `T12LifecycleTasksTest`.
- `try`/`finally`, `try-with-resources` и флаги «уже закрыто» не использовать: закрытие обеспечивают операторы.

Готовые классы, менять не нужно:

- `StreamMetrics` — считает подписки, элементы и запоминает, как поток закончился:
  - `subscribed()`;
  - `item()`;
  - `finished(SignalType)`.
- `ReportStorage` — файлы отчётов:
  - `open(name)` — синхронно открывает файл, журнал `open:<имя>`;
  - у файла `lines()` — строки;
  - у файла `close()` — закрыть, журнал `close:<имя>`;
  - файл `broken.csv` отдаёт одну строку, затем ошибку `Ошибка чтения broken.csv`.
- `UploadTarget` — внешнее хранилище, все операции асинхронные:
  - `begin()` — открывает сессию, журнал `begin`;
  - у сессии `write(rows)` — пишет строки, результат — их число, журнал `write:N`;
  - у сессии `commit()` и `rollback()` — журнал `commit`, `rollback`.

## Задача 1. Метрики потока

**Ситуация:**

Для мониторинга нужно знать о любом потоке:

- сколько раз на него подписались;
- сколько элементов прошло;
- чем он закончился — успехом, ошибкой или отменой.

**Что сделать:**

`withMetrics(Flux<String> source, StreamMetrics metrics)` — элементы те же, что у источника.

**Ожидаемый результат:**

| Сценарий | Подписок | Элементов | Чем закончился |
|---|---|---|---|
| `a, b, c`, завершение | 1 | 3 | `ON_COMPLETE` |
| `a`, затем ошибка | 1 | 1 | `ON_ERROR` |
| `a, b, c`, подписчик взял один и отказался | 1 | 1 | `CANCEL` |
| вызов метода без подписки | 0 | 0 | — |

## Задача 2. Прочитать файл отчёта и закрыть его в любом случае

**Ситуация:**

Отчёт читается из файла построчно. Незакрытые файлы копятся, и кончаются дескрипторы.

Поэтому файл закрывается всегда:

- после чтения;
- при ошибке чтения;
- когда читатель бросил на середине.

**Что сделать:**

`readReport(ReportStorage storage, String name)`.

**Ожидаемый результат:**

| Сценарий | Строки | Журнал |
|---|---|---|
| `orders.csv` | `id;amount`, `7;780.00`, `8;780.00` | `open:orders.csv`, `close:orders.csv` |
| `broken.csv` | `id;amount`, затем ошибка `Ошибка чтения broken.csv` | `open:broken.csv`, `close:broken.csv` |
| `orders.csv`, читатель взял одну строку и отказался | `id;amount` | `open:orders.csv`, `close:orders.csv` |
| до подписки | — | пусто |
| две подписки | — | два открытия и два закрытия |

## Задача 3. Загрузка строк в сессию хранилища

**Ситуация:**

Строки загружаются во внешнее хранилище через сессию:

1. Сессию открывают.
2. Пишут строки.
3. Обязательно завершают:
   - при успехе — подтверждают;
   - при ошибке и при отмене — откатывают.

Ни одна операция не блокирует поток.

**Что сделать:**

`upload(UploadTarget target, Flux<String> rows)` — число записанных строк.

**Ожидаемый результат:**

| Строки | Результат | Журнал |
|---|---|---|
| `a, b, c` | 3 | `begin`, `write:3`, `commit` |
| `a`, затем ошибка `битая строка` | эта ошибка доходит до вызывающего | `begin`, `rollback` |
| не кончаются, вызывающий отменил подписку | — | `begin`, `rollback` |

## Задача 4. Импорт количеств с меткой места сборки

**Ситуация:**

Импорт количеств из файла иногда падает на неверной строке.

- в логах видна `NumberFormatException` и стек из внутренностей Reactor;
- какая именно цепочка упала — непонятно.

Нужна метка, по которой ошибку найдут в коде.

**Что сделать:**

`importQuantities(Flux<String> raw)`.

1. Результат — числа из строк.
2. Метка — `импорт количеств`.

**Ожидаемый результат:**

Вход `5, x, 7`:

- приходит 5, затем ошибка;
- тип ошибки — по-прежнему `NumberFormatException`;
- среди её suppressed-исключений есть сообщение со строкой `импорт количеств`.

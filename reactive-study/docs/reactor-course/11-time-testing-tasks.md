- Тесты 1–4 используют виртуальное время: настоящие сутки никто не ждёт.
- Поэтому операторы времени в решении создаются при вызове метода, а не заранее в полях.
- `Thread.sleep` и свои таймеры не использовать.

## Задача 1. Напоминание через сутки

**Ситуация:**

Через сутки после оформления заказа клиенту приходит напоминание об отзыве.

**Что сделать:**

`reminder(int orderId)`.

**Ожидаемый результат:**

Заказ 7:

1. 23 часа — ничего.
2. Ещё час — `Напоминание: заказ 7`, поток завершён.
3. Тест идёт меньше 2 секунд реального времени.

## Задача 2. Три сигнала «пульс»

**Ситуация:**

При подключении клиент получает три сигнала «я на связи» с интервалом 10 секунд, затем поток закрывается.

**Что сделать:**

`heartbeat()`.

**Ожидаемый результат:**

| Время | Сигнал |
|---|---|
| 0–9 с | ничего |
| 10 с | `пульс 1` |
| 20 с | `пульс 2` |
| 30 с | `пульс 3`, затем завершение |

## Задача 3. Ждать готовности отчёта

**Ситуация:**

Отчёт строится на стороне банка. Статус проверяют так:

1. Первый раз — сразу.
2. Потом каждые 5 секунд, не больше 6 проверок всего.
3. Статус `READY` — вернуть его и больше не спрашивать.
4. За 6 проверок не готов — ошибка.

**Что сделать:**

`pollUntilReady(Mono<String> status)`.

Параметр `status` при каждой подписке заново спрашивает статус: `PENDING` или `READY`.

**Ожидаемый результат:**

| Статус | Результат | Проверок |
|---|---|---|
| готов на третьей проверке | `READY` на 10-й секунде (проверки на 0, 5, 10 с) | ровно 3 |
| не готов никогда | за 25 секунд — `IllegalStateException` «Отчёт не готов после 6 проверок» | 6 |

## Задача 4. Поиск по мере ввода

**Ситуация:**

Поиск товаров в магазине:

- пока пользователь печатает, запросы не нужны;
- запрос уходит, когда пользователь 300 мс ничего не вводил;
- ввод, после которого раньше чем через 300 мс пришёл новый, не ищется.

**Что сделать:**

`searchTerms(Flux<String> typed)` — строки, по которым нужно искать.

**Ожидаемый результат:**

1. `r`, через 100 мс `re`, через 100 мс `rea`.
2. 299 мс после `rea` — ничего. На 300-й мс — `rea`.
3. `reactor`, через 300 мс — `reactor`.

## Задача 5. Тест ночной выгрузки

**Ситуация:**

Готовый `ReportScheduler.nightlyRun()`:

- через 3 часа после подписки сообщает `выгрузка начата`;
- ещё через 30 минут — `выгрузка завершена`.

Класс менять нельзя. Нужен тест, который это проверяет и идёт доли секунды.

**Что сделать:**

Тело метода `nightlyRun()` в `T11ReportSchedulerTest`.

**Требования к тесту:**

1. До 3 часов — ни одного сигнала.
2. На 3-м часу — `выгрузка начата`.
3. Следующие 29 минут — ни одного сигнала.
4. На 30-й минуте — `выгрузка завершена` и завершение.
5. Тест идёт меньше 2 секунд реального времени.

**Как проверить, что тест настоящий:**

1. Временно поменяйте в `ReportScheduler` 3 часа на 4.
2. Ваш тест должен упасть.
3. Верните 3 часа.

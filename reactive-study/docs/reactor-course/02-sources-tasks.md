## Задача 1. Цена в момент подписки

**Ситуация:**

Витрина собирает описание запроса цены заранее, а выполняет его, когда покупатель открывает карточку.

Цена должна быть свежей на каждое открытие.

**Что сделать:**

`currentPrice(String sku)`.

1. Вызов метода к шлюзу не обращается.
2. Каждая подписка — новый вызов шлюза и цена на этот момент.
3. Для неизвестного артикула — пустой ответ, без ошибки.

**Ожидаемый результат:**

| Действие | Результат | Вызовов шлюза |
|---|---|---|
| вызвать метод, не подписываться | — | 0 |
| две подписки на `currentPrice("SKU-1")` | 199.90 и 199.90 | 2 |
| подписка на `currentPrice("SKU-404")` | пусто | 1 |

## Задача 2. Проверка количества

**Ситуация:**

Корзина передаёт количество товара. Неположительное количество — ошибка ввода.

Вызывающая цепочка обрабатывает ошибки своими средствами и ждёт их сигналом.

**Что сделать:**

`validatedQuantity(int quantity)`.

1. Положительное количество — вернуть его.
2. Ноль или меньше — ошибка `IllegalArgumentException` с сообщением `Количество должно быть больше нуля: <число>`.
3. Сам вызов метода при неверном количестве не бросает исключение.

**Ожидаемый результат:**

| Вызов | Результат |
|---|---|
| `validatedQuantity(3)` | 3 |
| `validatedQuantity(0)` | ошибка «Количество должно быть больше нуля: 0» |
| `validatedQuantity(-2)` | ошибка «Количество должно быть больше нуля: -2» |

## Задача 3. Номера страниц

**Ситуация:**

Выгрузка каталога идёт постранично. Известно число записей и размер страницы.

Нужны номера страниц, начиная с 1. Последняя страница может быть неполной.

**Что сделать:**

`pageNumbers(int totalItems, int pageSize)`.

**Ожидаемый результат:**

| Записей | Размер страницы | Номера |
|---|---|---|
| 95 | 10 | 1 … 10 |
| 100 | 25 | 1, 2, 3, 4 |
| 0 | 10 | пусто |

## Задача 4. Паузы перед повторным звонком

**Ситуация:**

Колл-центр перезванивает клиенту, который не ответил:

- первая пауза — 1 минута;
- каждая следующая вдвое длиннее;
- пауза длиннее заданного предела уже не нужна.

**Что сделать:**

`callbackDelays(int maxMinutes)`.

1. Выдать паузы в минутах: 1, 2, 4, 8, … — пока пауза не больше `maxMinutes`.
2. Следующая пауза вычисляется из предыдущей. Готовый список пауз в коде не заводить.
3. Каждый подписчик получает расписание с начала.

**Ожидаемый результат:**

| `maxMinutes` | Паузы |
|---|---|
| 20 | 1, 2, 4, 8, 16 |
| 16 | 1, 2, 4, 8, 16 |
| 5 | 1, 2, 4 — и для второго подписчика тоже |
| 0 | пусто |

## Задача 5. Артикулы из старой системы

**Ситуация:**

Старая система отдаёт список артикулов синхронным вызовом `Supplier<List<String>>`. Она:

- медленная;
- иногда вместо пустого списка возвращает `null`;
- иногда падает.

Вызывать её можно только тогда, когда список действительно нужен.

**Что сделать:**

`skusFromLegacy(Supplier<List<String>> legacyCall)`.

1. Вызов метода старую систему не трогает.
2. Каждая подписка — новый вызов старой системы.
3. Артикулы выдаются по одному, по порядку.
4. `null` вместо списка — пустой ответ.
5. Исключение старой системы — ошибка сигналом. Сам метод не бросает.

**Ожидаемый результат:**

| Старая система | Результат | Вызовов |
|---|---|---|
| `SKU-1`, `SKU-3`, две подписки | `SKU-1`, `SKU-3` дважды | 0 до подписки, 2 после |
| `null` | пусто | |
| бросает «старая система недоступна» | ошибка с этим сообщением | |

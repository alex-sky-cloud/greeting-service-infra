## Задача 1. Профиль клиента из трёх источников

**Ситуация:**

Экран профиля показывает имя клиента, число его заказов и бонусный баланс.

Три запроса не зависят друг от друга.

**Что сделать:**

`profile(int customerId)`.

1. Данные берутся так:
   - имя — из `customers.findById`;
   - число заказов — из `orders.findByCustomerIdOrderById`;
   - баланс — из `bonusAccounts.findById`.
2. Запросы не ждут друг друга.
3. Клиента нет — пустой ответ.

**Ожидаемый результат:**

| Клиент | Профиль |
|---|---|
| 5 | Дарья Миронова, заказов 4, бонусов 1000 |
| 8 | Зоя Белова, заказов 0, бонусов 50 |
| 99 | пусто |

## Задача 2. Приветствие с промокодом

**Ситуация:**

В письме — приветствие и промокод, если он есть.

Отсутствие промокода — обычная ситуация, приветствие всё равно нужно.

**Что сделать:**

`greeting(int customerId)`.

1. Есть промокод: `<имя>, ваш промокод: <код>`.
2. Нет промокода: `<имя>, промокода нет`.
3. Клиента нет — пустой ответ.

**Ожидаемый результат:**

| Клиент | Строка |
|---|---|
| 1 | `Анна Смирнова, ваш промокод: GOLD-1` |
| 2 | `Борис Котов, промокода нет` |
| 99 | пусто |

## Задача 3. Общая лента склада и курьера

**Ситуация:**

Диспетчер видит одну ленту событий заказа. События приходят из двух систем:

- склада;
- курьерской службы.

В ленте они должны появляться в момент возникновения.

**Что сделать:**

`liveFeed(Flux<String> warehouse, Flux<String> courier)`.

**Ожидаемый результат:**

| Время | Событие | Источник |
|---|---|---|
| 100 мс | `склад: принят` | склад |
| 150 мс | `курьер: выехал` | курьер |
| 200 мс | `склад: собран` | склад |

Лента — в этом порядке: событие курьера между событиями склада.

## Задача 4. Сначала архив, потом новые события

**Ситуация:**

При открытии истории заказа сначала показываются все архивные события, потом новые.

Систему новых событий нельзя даже спрашивать, пока архив не прочитан до конца: иначе события перепутаются.

**Что сделать:**

`history(Flux<String> archive, Flux<String> live)`.

**Ожидаемый результат:**

`архив-1`, `архив-2`, `новое-1`; подписка на `live` — только после завершения `archive`.

## Задача 5. Закрыть заказ и уведомить клиента

**Ситуация:**

Закрытие заказа — два шага в журнале:

1. «Закрыт».
2. «Клиент уведомлён».

Уведомлять до закрытия нельзя. Вызывающему нужен ответ `Заказ <N> закрыт`.

**Что сделать:**

`closeOrder(int orderId)`.

1. До подписки журнал пуст.
2. «Клиент уведомлён» — строго после «закрыт», хотя уведомление само по себе быстрее.
3. После обоих шагов — строка `Заказ <N> закрыт`.

**Ожидаемый результат:**

Для заказа 7:

- ответ — `Заказ 7 закрыт`;
- журнал — `заказ 7: закрыт`, `заказ 7: клиент уведомлён`.

## Задача 6. Прогрев перед открытием смены

**Ситуация:**

Перед открытием смены нужно прогреть кэши: цены, остатки, тарифы. Шаги независимы, результатов у них нет.

- закончены все шаги — смена открывается;
- хоть один упал — смена не открывается.

**Что сделать:**

`warmUp(List<Mono<Void>> steps)`.

1. Шаги выполняются одновременно.
2. Ответ — завершение без значения после последнего шага.
3. Ошибка любого шага — ошибка всего прогрева.

**Ожидаемый результат:**

| Шаги | Результат |
|---|---|
| 100, 200, 300 мс | завершение; все три выполнены; меньше 500 мс |
| 100 мс и шаг с ошибкой «кэш цен не прогрет» через 50 мс | ошибка «кэш цен не прогрет» |

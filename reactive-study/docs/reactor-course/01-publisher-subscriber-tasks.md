## Задача 1. Журнал сигналов

**Ситуация:**

Выгрузка из внешней системы иногда обрывается. Чтобы разбираться с инцидентами, нужен журнал: какие сигналы получил подписчик и в каком порядке.

**Что сделать:**

Метод `recordSignals(Publisher<String> source)`.

1. Подписаться на `source` и принимать все элементы без ограничения.
2. Каждый полученный сигнал записать в журнал строкой:
   - получение подписки — `onSubscribe`;
   - элемент `X` — `onNext:X`;
   - ошибка с сообщением `M` — `onError:M`;
   - завершение — `onComplete`.
3. Вернуть журнал. Источники в тестах синхронные: к моменту возврата из метода все сигналы уже пришли.

**Ожидаемый результат:**

| Источник | Журнал |
|---|---|
| элементы `A`, `B` | `onSubscribe`, `onNext:A`, `onNext:B`, `onComplete` |
| пустой | `onSubscribe`, `onComplete` |
| `A`, затем ошибка «нет связи» | `onSubscribe`, `onNext:A`, `onError:нет связи` |

## Задача 2. По одной позиции за раз

**Ситуация:**

Терминал на складе показывает одну позицию на экране. Следующую он берёт, только когда кладовщик обработал текущую.

После заданного числа позиций смена заканчивается. Остальные позиции не нужны, и источник должен об этом узнать.

**Что сделать:**

Метод `takeOneByOne(Publisher<Integer> source, int limit)`.

1. Получать позиции строго по одной: следующую просить только после получения предыдущей.
2. Получив `limit` позиций, сообщить источнику, что больше не нужно.
3. Если источник закончился раньше, просто вернуть то, что пришло. Сообщать об отказе в этом случае не нужно.
4. Вернуть полученные позиции по порядку.

**Ожидаемый результат:**

| Источник | `limit` | Результат | Что видит источник |
|---|---|---|---|
| 10, 20, 30, … 1000 | 3 | 10, 20, 30 | три запроса по 1, затем отказ |
| 5, 6 | 3 | 5, 6 | отказа нет |

## Задача 3. Дождаться асинхронной выгрузки

**Ситуация:**

Утилита командной строки выгружает пачки из асинхронного источника: пачки приходят с другого потока.

Утилите нужен готовый список, но ждать вечно нельзя.

**Что сделать:**

Метод `collectWithin(Flux<String> asyncSource, Duration maxWait)`.

1. Собрать все пачки в список и вернуть его после завершения источника.
2. Если источник не завершился за `maxWait` — отказаться от подписки и бросить `java.util.concurrent.TimeoutException`.
3. Если источник завершился ошибкой — бросить `IllegalStateException`, причиной (`cause`) которого будет исходная ошибка.
4. `block…` методы `Flux` не использовать: ожидание пишется вручную, средствами стандартной библиотеки.

**Ожидаемый результат:**

| Источник | Результат |
|---|---|
| три пачки с интервалом 50 мс, ждать 2 с | `пачка-0`, `пачка-1`, `пачка-2` |
| не выдаёт ничего, ждать 200 мс | `TimeoutException`, источник получил отказ |
| одна пачка, затем ошибка «битая пачка» | `IllegalStateException`, корневая причина — `IllegalArgumentException("битая пачка")` |

## Задача 4. Карточка и заказы клиента

**Ситуация:**

Экрану «Клиент» нужны карточка клиента и его заказы из таблиц `rc_customers` и `rc_orders`.

Для этого есть готовые репозитории, сам запрос писать не нужно.

**Что сделать:**

В классе `T01CustomerQueries`.

1. `customerById(int customerId)` — карточка клиента. Если клиента нет — пустой ответ, без ошибки.
2. `ordersOfCustomer(int customerId)` — заказы клиента по возрастанию номера. Нет заказов — завершение без элементов.

**Подсказка:**

- в классе уже есть поля `customers` и `orders`;
- какие методы есть у репозиториев, видно в `reactorcourse/common`.

**Ожидаемый результат:**

| Вызов | Результат |
|---|---|
| `customerById(3)` | Вера Лаптева, Самара |
| `customerById(99)` | пусто |
| `ordersOfCustomer(3)` | заказы 7, 8, 9 |
| `ordersOfCustomer(8)` | пусто |

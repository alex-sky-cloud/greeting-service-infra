## Задача 1. Перевод бонусов между клиентами

**Ситуация:**

Клиент дарит бонусы другому клиенту.

Списание и зачисление проходят вместе или не проходят вовсе.

**Что сделать:**

`transferBonus(int fromCustomerId, int toCustomerId, int points)`.

1. Если у отправителя не хватает бонусов — `InsufficientBonusException(fromCustomerId, причина)`. Причина — исключение базы.
2. Если какого-то счёта нет — `AccountNotFoundException(customerId)`.

**Ожидаемый результат:**

| Перевод | Результат | Балансы после |
|---|---|---|
| 1 → 2, 100 | завершение без значения | 1 — 400, 2 — 100 |
| 1 → 99, 100 | `Бонусный счёт клиента 99 не найден` | 1 — 500 |
| 2 → 3, 50 | `У клиента 2 не хватает бонусов`, причина — `DataIntegrityViolationException` | 2 — 0, 3 — 120 |
| вызов без подписки | — | 1 — 500 |

## Задача 2. Оплата заказа один раз

**Ситуация:**

Кнопку «Оплатить» нажимают дважды, запросы приходят почти одновременно.

- платёж по заказу должен быть один;
- повторная оплата — не ошибка: клиенту сообщают, что заказ уже оплачен.

**Что сделать:**

`payOrder(int orderId)` — сумма платежа берётся из заказа.

**Ожидаемый результат:**

| Вызов | Результат | Платежей в `rc_payments` |
|---|---|---|
| `payOrder(7)` | `Заказ 7 оплачен на 780.00` | 1 |
| второй `payOrder(7)` | `Заказ 7 уже оплачен` | по-прежнему 1 |
| `payOrder(999)` | `OrderNotFoundException` «Заказ 999 не найден» | 0 |

## Задача 3. Аудит вручённых заказов пачками в одной транзакции

**Ситуация:**

По всем вручённым заказам нужно записать строку аудита с сообщением `аудит`:

- пишем пачками по 4 номера;
- пачки — по одной;
- аудит — единый документ: все строки записываются одной транзакцией.

**Что сделать:**

`auditDeliveredOrders()` — сколько строк записано.

**Ожидаемый результат:**

- результат — 10;
- в `rc_audit_log` номера `1, 2, 5, 7, 8, 11, 12, 13, 17, 20`;
- все строки записаны одной транзакцией. Тест проверяет это запросом:

```sql
select count(distinct xmin::text) from reactive_study.rc_audit_log;   -- 1
```

## Задача 4. Аудит списка заказов: всё или ничего

**Ситуация:**

Оператор присылает список номеров заказов для аудита.

- номера пишутся по одному, по порядку;
- номер `0` или меньше — ошибка `InvalidOrderIdException("Неверный номер заказа: <id>")`;
- при ошибке в журнале не должно остаться ни одной строки из этого списка.

**Что сделать:**

`auditAllOrNothing(List<Integer> orderIds)` — сколько строк записано.

**Ожидаемый результат:**

| Список | Результат | Строк в журнале |
|---|---|---|
| `[7, 8]` | 2 | 2 |
| `[7, 8, 0, 9]` | ошибка «Неверный номер заказа: 0» | 0, хотя 7 и 8 успели записаться до ошибки |

## Задача 1. Справочник тарифов загружается один раз

**Ситуация:**

Тарифы нужны на каждой странице оформления заказа, а внешний сервис медленный.

- тарифы меняются раз в год — достаточно загрузить их один раз за жизнь приложения;
- но не при старте: только когда они впервые понадобятся.

**Что сделать:**

`TariffDirectory.tariffs()`.

**Ожидаемый результат:**

1. Сразу после создания справочника загрузок 0.
2. Три вызова `tariffs()` с подпиской — каждый раз `[Базовый, Плюс, Премиум (v1)]`.
3. Загрузка ровно одна.

## Задача 2. Справочник тарифов с устареванием

**Ситуация:**

В другом сервисе тарифы меняются чаще: показывать устаревшие дольше заданного срока нельзя.

Срок передаётся в конструктор.

**Что сделать:**

`ExpiringTariffDirectory.tariffs()`.

**Ожидаемый результат:**

Срок 200 мс:

1. Два обращения подряд — оба `[…, Премиум (v1)]`, загрузка одна.
2. Через 300 мс обращение даёт `[…, Премиум (v2)]`, загрузок 2.

## Задача 3. Одна лента котировок на всех зрителей

**Ситуация:**

Котировки приходят из платного источника: каждая подписка на него стоит денег.

- зрителей много, они подключаются в разное время;
- опоздавшему старые котировки не нужны.

**Что сделать:**

`sharedFeed(Flux<Long> source)`.

**Ожидаемый результат:**

Источник выдаёт 0…5 раз в секунду (время в тесте виртуальное):

- первый зритель подключился сразу — получил `0, 1, 2, 3, 4, 5`;
- второй подключился через 2 секунды — получил `2, 3, 4, 5`;
- подписка на источник одна.

## Задача 4. Начать трансляцию, когда подключатся двое

**Ситуация:**

Онлайн-урок для пары учеников:

- начинать, только когда оба на месте;
- показывать обоим с начала.

**Что сделать:**

`startWhenTwo(Flux<Integer> source)`.

**Ожидаемый результат:**

1. Первый ученик подписался — подписок на источник 0, он ничего не получил.
2. Подписался второй — подписка на источник одна.
3. Оба получили `1, 2, 3`.

## Задача 5. Шина уведомлений

**Ситуация:**

Сервис рассылает уведомления тем, кто сейчас на связи:

- пропущенные уведомления не повторяются: кто подключился позже, видит только новые;
- если на связи никого нет, уведомление теряется, и это нормально.

**Что сделать:**

`NotificationBus.publish(String)` и `NotificationBus.messages()`.

**Ожидаемый результат:**

1. `publish("до всех")` — подписчиков нет, ошибки нет.
2. Подписался A, затем `publish("для A")`.
3. Подписался B, затем `publish("для A и B")`.

Итог:

- A получил `для A`, `для A и B`;
- B получил `для A и B`.

## Задача 6. Табло последних цен

**Ситуация:**

Новый зритель табло:

- сразу видит три последние цены — даже если они появились, когда табло никто не смотрел;
- потом видит новые.

**Что сделать:**

`PriceBoard.publish(int)` и `PriceBoard.prices()`.

**Ожидаемый результат:**

1. Опубликованы 1, 2, 3, 4, 5 без зрителей.
2. Новый зритель сразу получает `3, 4, 5`.
3. После `publish(6)` он получает `6`.

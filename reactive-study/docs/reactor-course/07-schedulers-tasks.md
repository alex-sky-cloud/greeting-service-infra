## Задача 1. Остаток из старой системы, не занимая чужой поток

**Ситуация:**

Сервис на WebFlux должен спрашивать остаток у старой системы. Её клиент блокирует поток на 200 мс.

Поток, который подписался, ждать не должен: он обслуживает другие запросы.

**Что сделать:**

`stock(String sku)`.

1. До подписки склад не вызывается.
2. Вызов `subscribe()` возвращается быстрее 100 мс.
3. Вызов клиента идёт на потоке из пула для блокирующих задач.

**Ожидаемый результат:**

- `stock("SKU-3")` — 7;
- клиент вызван один раз, на потоке `boundedElastic-…`.

## Задача 2. Форматирование на потоках для вычислений

**Ситуация:**

Остатки поступают из источника, который работает на своём потоке. Этот поток трогать нельзя.

Форматирование строк — тяжёлое вычисление, его место — на потоках для вычислений.

**Что сделать:**

`formatOnParallel(Flux<Integer> stocks, String sku)`.

1. Источник выдаёт элементы на том потоке, на котором его подписали.
2. Каждый вызов форматировщика — на потоке `parallel-…`.

**Ожидаемый результат:**

Остатки 10, 7, 3 для `SKU-1`:

- строки `SKU-1: 10 шт.`, `SKU-1: 7 шт.`, `SKU-1: 3 шт.`;
- источник работал на потоке теста;
- три вызова форматировщика — все на `parallel-…`.

## Задача 3. Отчёт по остаткам

**Ситуация:**

Ночной отчёт: остатки по списку артикулов.

- чтение из старой системы — на пуле для блокирующих задач;
- форматирование — на пуле для вычислений;
- строки — в порядке списка.

**Что сделать:**

`stockReport(List<String> skus)`.

**Ожидаемый результат:**

Артикулы `SKU-1`, `SKU-2`, `SKU-3`:

- строки `SKU-1: 10 шт.`, `SKU-2: 0 шт.`, `SKU-3: 7 шт.`;
- три вызова склада — на `boundedElastic-…`;
- три вызова форматировщика — на `parallel-…`.

## Задача 4. Остатки по всем артикулам одновременно

**Ситуация:**

Перед акцией нужны остатки по пяти артикулам сразу.

По очереди это 1 секунда, а ответ нужен быстрее.

**Что сделать:**

`stocksConcurrently(List<String> skus)` — карта «артикул → остаток».

**Ожидаемый результат:**

Для `SKU-1` … `SKU-5`:

- карта `{SKU-1=10, SKU-2=0, SKU-3=7, SKU-4=3, SKU-5=12}`;
- быстрее чем за 600 мс;
- пять вызовов склада на пяти разных потоках.

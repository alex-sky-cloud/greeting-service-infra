## Задача 1. Цена со скидкой без лишних объектов

**Ситуация:**

После релиза акций каталог стал отвечать медленно, а GC-лог показывает молодую сборку каждые 0,2 секунды. Утечки нет: после сборки остаётся 8–10 МБ, как в [разделе 1 теории](07-allocations.md#1-скорость-выделения-памяти).

**Что сделать:**

`priceFor(String sku, int discountPercent)` — та же цена, что у `LegacyCatalog`, без лишних объектов.

1. Артикул сравнивается без учёта регистра и пробелов по краям.
2. Цена в копейках со скидкой в процентах, округление вниз.
3. Товара нет — `-1`.
4. Ответ должен совпасть со старым каталогом для любых артикулов и скидок.

**Ожидаемый результат:**

| Артикул | Скидка | Цена |
|---|---|---|
| `SKU-00001` | 0 | 1 113 |
| `SKU-00001` | 15 | 946 |
| `SKU-99999` | 15 | −1 |
| `" sku-00777 "`, `SKU-12345`, `SKU-50000`, `""` | 0, 7, 15, 100 | как у `LegacyCatalog` |

- 10 000 расчётов после прогрева — в среднем не больше 64 байт на расчёт. Тест печатает своё число.

**После теста ответьте в чате:**

1. Сколько байт на расчёт у вас и сколько у старого каталога?
2. Нужна ли была копия прайса «чтобы прайс не поменялся посреди расчёта»? Почему?

## Задача 2. Кто выделяет больше всех

**Ситуация:**

Сводка аллокаций JFR называет `HashMap.newNode` и `byte[]` — это JDK. Дежурному нужен список мест **в нашем коде**, как в [разделе 4 теории](07-allocations.md#4-первое-место-из-кода-приложения).

**Что сделать:**

`top(Path recording, int n)` — до `n` методов приложения, из которых выделено больше всего байт.

1. Считать только сэмплы выделения объектов, у которых есть стек.
2. Метод — первый кадр стека с классом из пакета `com.example.`: полное имя класса, точка, имя метода.
3. Байты — сумма весов сэмплов, а не число сэмплов.
4. Порядок — по байтам от большего к меньшему; при равенстве — по имени метода.

**Ожидаемый результат:**

- запись: 300 раз старый расчёт цены и 300 миниатюр по 64 КБ;
- первое место — `com.example.profcourse.t07.LegacyCatalog.priceFor`;
- второе — `com.example.profcourse.t07.ThumbnailService.thumbnail`;
- у первого байт больше, чем у второго, минимум втрое.

**После теста ответьте в чате:**

1. Почему считают сумму весов, а не число сэмплов?
2. Миниатюры выделяют по 64 КБ на штуку. Почему они не первые?

## Лабораторная. Каталог и сборки мусора

Подготовка терминалов — [00-plan.md, раздел «Лаборатория»](00-plan.md#лаборатория).

**Терминал 1** — каталог с GC-логом и записью JFR на 15 секунд:

```bash

mkdir -p build/lab
java -Xlog:gc:file=build/lab/catalog-gc.log \
  -XX:StartFlightRecording:duration=15s,filename=build/lab/catalog.jfr \
  -cp build/classes/java/main com.example.profcourse.lab.LabApp catalog
```

Через 20 секунд — `Ctrl+C`. Запишите последнее «в секунду» из терминала 1.

**Терминал 2** — частота сборок и что выделяется:

```bash

sed -n '40,45p' build/lab/catalog-gc.log
jfr view gc-pauses build/lab/catalog.jfr
jfr view allocation-by-class build/lab/catalog.jfr | head -8
jfr view allocation-by-site build/lab/catalog.jfr | head -8
jfr print --events jdk.ObjectAllocationSample --stack-depth 8 build/lab/catalog.jfr \
  | grep -B 7 'LegacyCatalog.priceFor' | head -10
```

**JMC** — **File → Open File…** → `build\lab\catalog.jfr`:

1. **Java Application → Memory**: щелчок по заголовку **Alloc Total**, затем по верхней строке — смотрите **Flame View** внизу.
2. **JVM Internals → Garbage Collections**: колонка **Longest Pause** и график **Heap Post GC**.

Где это на экране — [теория, «То же в JMC»](07-allocations.md#то-же-в-jmc).

**После задачи 1** — бюджет из теста:

```bash

./gradlew test --rerun --tests "com.example.profcourse.t07.*" | grep 'байт на расчёт'
```

**Ответьте в чате:**

1. Как часто идут молодые сборки и сколько освобождает каждая? Сколько это мегабайт в секунду?
2. Сколько мегабайт на одну цену выходит из ваших чисел? Совпадает ли с теорией?
3. Сколько пауз и какая суммарная пауза за 15 секунд по `gc-pauses`?
4. Какие классы и методы JDK наверху сводок и какой кадр приложения под ними?
5. Сколько байт на расчёт печатает тест после вашего исправления?
6. JMC: сколько гигабайт выделено под верхний класс страницы Memory и растёт ли линия Heap Post GC?
